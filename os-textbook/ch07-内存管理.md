## 7.1 从一个问题开始：程序 A 崩了，为什么 B 活得好好的？

你在浏览器里开一个网页，网页里的程序写错了一个指针，浏览器标签页"崩"了——
可你正在放歌的音乐软件毫无察觉，终端里的 `bash` 也照常接受输入。

这在今天是天经地义，可仔细想想，它其实很神奇：**所有程序明明共享同一根内存条**。
音乐软件的内存和浏览器的内存物理上就挨在一起，为什么一个写崩了，另一个毫发无损？
要是没有物业管理，大楼里一户人家 flood 了厨房，全楼跟着遭殃——早年没有内存
管理的个人计算机就是这样：**任何一个程序写野了指针，整台机器当场死机**，只能重启。

内存管理要解决的两个经典难题：

**难题一：两个程序都想要同一个地址，怎么办？**

编译器把你的 C 程序编译成 32 位可执行文件时，默认让代码从地址 `0x08048000`
开始。于是问题来了：音乐软件和浏览器**编译出来的指令都从 `0x08048000` 开始**，
两份程序同时运行，都"住"在这个地址上——它们不会互相覆盖吗？

**难题二：前一个程序忘收摊，后一个全乱套。**

程序 A 申请了一块内存，用完忘了还就退出了；程序 B 再来申请同一块，里面还躺着
A 的旧数据；B 拿它当自己的变量用，读到一堆"昨天的垃圾"。更糟的组合是：
A 还没退出，就顺手写了 B 正在用的内存——B 的账户余额可能就变成了乱码。

这两个难题指向内存管理的**两大任务**：

| 任务 | 俗名 | 一句话 |
|---|---|---|
| **保护（隔离）** | 别越界 | 每个进程有自己独立的地址空间，A 摸不到 B 的内存 |
| **复用（超卖）** | 会超卖 | 16MB 物理内存敢让"64 个进程 × 64MB"同时"在用" |

注意"超卖"这个词——它和航空公司的超售是一个思路：**卖出去的比实际拥有的多**，
赌的是不会所有人同时到场。0.11 敢给每个进程 64MB"地址空间"，整机却可能只有
16MB 物理内存，超卖比例高达 256 倍。它凭什么敢？这就是本章的主线剧情。

## 7.2 核心概念：地址的三级跳

### 7.2.1 主角登场：三种地址

程序员嘴里的"地址"其实有三种，它们层层转手，最后一次才落到真实的内存条上：

```
  程序 A 眼中的世界                      硬件眼中的世界
┌──────────────────────┐
│ 逻辑地址 0x00001234    │  程序里的地址（段 : 偏移）
│  "我家门牌 1234"       │  每个程序都以为自己从 0 开始
└──────────┬───────────┘
           │ ① 分段单元：段基址 + 偏移
           │   （A 的楼栋坐落在地皮的哪一段）
           ▼
┌──────────────────────┐
│ 线性地址 0x18001234    │  A 的段基址 = 6 × 64MB = 0x18000000
│  "6 号楼 1234 室"      │  一根线性地址"尺子"上的位置
└──────────┬───────────┘
           │ ② 分页单元：查页表，按 4KB 一页映射
           │   （房间号 → 真实土地）
           ▼
┌──────────────────────┐
│ 物理地址 0x00C34000    │  内存条上真实的那几个字节（16MB 内某处）
│  "城东 7 号地皮"       │
└──────────────────────┘
```

给三种地址各下一个定义：

- **逻辑地址（logical address）**：程序里写出来的地址，形式是"段：偏移"。
  你在 C 语言里打印一个指针，看到的其实是**偏移**那一半——段藏在段寄存器里，
  编译器和运行库帮你管着，你感觉不到它的存在；
- **线性地址（linear address）**：分段单元的输出。把段基址加上偏移，
  得到一个不分段的、从 0 到 4GB 的"一维"地址；
- **物理地址（physical address）**：分页单元的输出，真正发到内存条引脚上的地址。

> **一句话分工**：**分段负责隔离**——每家一个独立门牌区间，谁也够不着谁；
> **分页负责复用**——把门牌区间切成 4KB 的小页，灵活地摊到大地上，
> 图纸上画了不等于地上建了（7.3.2、7.3.3 的魔法全靠这一步）。

一个完整的比喻：**进程是一栋楼，分段是给每栋楼一个不重叠的楼栋号区间；
分页是把"房间号"统一映射到真实土地**。楼可以盖得很大（图纸上有 64MB 的房间），
但土地（物理内存）就一块，某个房间到底落在哪块地上、有没有打地基，
由另一本账——页表——说了算。

### 7.2.2 0.11 的分段：每家一栋 64MB 的楼

打开第 4 章见过的 `linux-0.11/kernel/fork.c` 第 52 行：

```c
new_data_base = new_code_base = nr * 0x4000000;   /* nr × 64MB */
```

`0x4000000` = 64MB，`nr` 是进程在进程表里的槽位号。0.11 给每个进程建一张私有的
**LDT（局部描述符表）**，里面登记两个段——代码段和数据段——**基址都是
`槽位号 × 64MB`**：0 号进程住 0~64MB，1 号住 64~128MB……64 个槽位 × 64MB =
4GB，恰好铺满 32 位线性空间。exec 装载新程序时再把数据段的**上限**设成 64MB
（`fs/exec.c` 第 161 行：`data_limit = 0x4000000`）。

于是难题一解了：两个程序的逻辑地址都是 `0x08048000` 没关系，A 的 0 号楼和
B 的 3 号楼，走完分段这一步就分流到不同的线性地址，**永远不会撞车**。
程序对此一无所知——它以为自己独占一台机器。这就是**隔离**的力量：
隔离做得好，程序连"别人存在"都不需要知道。

但注意，64MB 只是**户型图**。进程真能摸到 64MB 吗？第 4 章练习 4.4 卖的关子
在这里揭晓：物理内存一共可能才 16MB，64MB 是"门牌区间"的宽度，不是实占。
真正决定"哪个房间落在哪块地上、地基打没打"的，是下一节的主角——页表。

### 7.2.3 0.11 的分页：4KB 一页，二级页表

分页把线性地址空间切成固定大小的**页（page）**——x86 上每页 4KB；
物理内存也切成同样大小的**页框（page frame）**。页表干的事就一件：
**把"第几页"映射到"第几个页框"**，顺带记下权限（可读？可写？在内存里吗？）。

4GB 空间有 100 多万页，要是只用一张大表，每张表 4MB 大小——每个进程都得背
一张，内存直接被表吃光。386 的方案是把地址**拆成两级**：32 位线性地址 =
**10 位目录号 + 10 位页表号 + 12 位页内偏移**：

```
 线性地址   31          22 21          12 11          0
         ┌───────────────┬───────────────┬─────────────┐
         │  目录号 (10位) │ 页表号 (10位)  │ 页内偏移(12位)│
         └───────┬───────┴───────┬───────┴──────┬──────┘
                 │               │              │
      ① 用目录号  │               │              │
        查页目录  ▼               │              │
      ┌─────────────┐            │              │
      │ 页目录(1024项)│            │              │
      │ 0.11 放在    │            │              │
      │ 物理地址 0   │            │              │
      └──────┬──────┘            │              │
             │ 取出一张页表的位置 │              │
             ▼                   │              │
      ┌─────────────┐   ②用页表号 ▼              │
      │ 某一张页表    │──►┌─────────────┐        │
      │  (1024 项)   │   │ 页表(1024 项) │        │
      └─────────────┘   └──────┬──────┘        │
                               │ 取出物理页基址  │ ③基址+偏移
                               ▼               ▼
                        ┌─────────────────────────────┐
                        │ 物理页基址(高20位) + 页内偏移   │
                        │          = 物理地址           │
                        └─────────────────────────────┘
```

三步查完。这套"地图的地图"设计好在：**目录项说"这 4MB 我没用到"，就可以整段
不建页表**——1024 个目录项对应 1024 个 4MB 区间，没盖楼的图纸不画施工图。
每个 10 位编号管 1024 项 × 4KB = 4MB，这也解释了 7.3.2 里
`copy_page_tables()` 为什么要求地址必须按 **4MB 对齐**——它按"整个目录项"
为单位复制页表。

> **TLB 是什么？** 三步查表要走两趟内存，太慢。CPU 把最近的翻译结果缓存在
> **TLB（Translation Lookaside Buffer，快表）**里——一个硬件级"翻译结果缓存"，
> 命中时零趟内存直达。改了页表就得让 TLB 失效，0.11 里的做法粗暴而正确：
> `memory.c` 第 39~40 行的 `invalidate()` 宏——往 CR3 寄存器写个 0，整本缓存作废重来（7.3.1 详说）。

0.11 建了几张页表？打开第 3 章见过的 `linux-0.11/boot/head.s`：页目录
`_pg_dir` 放在物理地址 0（第 16 行），后面跟 **4 张页表** pg0~pg3（第 114~124
行 `.org 0x1000`~`.org 0x4000`）。`setup_paging`（第 198~218 行）把 4 张页表
填满并打开 CR0 的 PG 位。算一笔账：

```
4 张页表 × 1024 项/张 × 4KB/项 = 16MB
```

**0.11 最多管理 16MB 物理内存**——head.s 第 110~112 行 Linus 自己写了注释：
"用 4 张页表覆盖 16MB，内存更大的朋友只能自己动手了"。这 4 张表在启动时把
线性地址 0~16MB **恒等映射**（线性 = 物理）到自身，好让内核先跑起来；之后
每个用户进程的页表由 mm 模块按需增删——把进程的线性地址映射到 16MB 里
随便哪个空闲页框。楼栋归分段管，土地分配归分页管，两级分工明确。

## 7.3 源码导读：mm/memory.c——430 行的"土地管理局"

本章的主角文件只有 430 行，却装下了现代内存管理的全部核心思想。先放地图：

| 函数（memory.c 行号） | 干什么 | 俗名 |
|---|---|---|
| `get_free_page()`（63） | 找一个空闲物理页并清零 | 领一块新地皮 |
| `free_page()`（89） | 归还物理页，引用计数减一 | 还地皮 |
| `copy_page_tables()`（150） | fork 时复制页表并置只读 | 复印户型图（COW 起点） |
| `put_page()`（197） | 把物理页挂进页表某线性地址 | 在地图上钉一枚图钉 |
| `un_wp_page()`（221） | COW 的"真正复印"发生地 | 谁先写谁复印 |
| `do_wp_page()`（247） | 页保护异常处理：写到共用页了 | COW 的第一现场 |
| `do_no_page()`（365） | 访问的页还不在内存：按需调页 | 现场建房 |
| `mem_init()`（399） | 开机时把登记簿初始化 | 土地局挂牌 |

### 7.3.1 源码导读一：mem_map[]——物理页的格柜登记簿

先看常量（memory.c 第 43~47 行，注释说"改动须与 head.s 同步"）：

```c
#define LOW_MEM 0x100000                  /* 1MB：以下的内存内核自用 */
#define PAGING_MEMORY (15*1024*1024)      /* 可分页的物理内存：15MB */
#define PAGING_PAGES (PAGING_MEMORY>>12)  /* 15MB / 4KB = 3840 页 */
#define MAP_NR(addr) (((addr)-LOW_MEM)>>12)  /* 物理地址 → 格柜编号 */
#define USED 100
```

16MB 物理内存，**最低 1MB（`LOW_MEM` 以下）是内核的地盘，不参与分页**——
内核代码、数据、页目录页表都住那里。剩下 15MB 切成 3840 个 4KB 页框，
用一行定义一个数组来记账（第 57 行）：

```c
static unsigned char mem_map [ PAGING_PAGES ] = {0,};
```

`mem_map[]` 就是一排 **3840 个格子的柜子**：`mem_map[i] == 0` 表示第 i 个
页框空着；非 0 表示被几个引用占着（普通占用是 1，两进程共用的 COW 页是 2，
以此类推）。开机时 `mem_init()`（第 399 行）先把全部格子标成 USED，再把
内核结尾（`start_mem`）到内存顶端这一段逐一清零释放——中间那截"内核 +
缓冲区"保持占用，谁也分不走。

**领地皮：get_free_page()**（第 63 行）。这个函数是内联汇编，原样贴出（第 63~83 行）再拆——其实是一个"从高往低找空格"的循环：

```c
unsigned long get_free_page(void)
{
register unsigned long __res asm("ax");

__asm__("std ; repne ; scasb\n\t"
	"jne 1f\n\t"
	"movb $1,1(%%edi)\n\t"
	"sall $12,%%ecx\n\t"
	"addl %2,%%ecx\n\t"
	"movl %%ecx,%%edx\n\t"
	"movl $1024,%%ecx\n\t"
	"leal 4092(%%edx),%%edi\n\t"
	"rep ; stosl\n\t"
	"movl %%edx,%%eax\n"
	"1:"
	:"=a" (__res)
	:"0" (0),"i" (LOW_MEM),"c" (PAGING_PAGES),
	"D" (mem_map+PAGING_PAGES-1)
	:"di","cx","dx");
return __res;
}
```

| 汇编（第 67~77 行） | 人话 |
|---|---|
| `std ; repne ; scasb` | 从 `mem_map` **末尾**往前扫，找值为 0 的字节（空格） |
| `jne 1f` | 扫到头也没空格 → 返回 0（eax=0 就是"没页了"） |
| `movb $1,1(%%edi)` | 找到了：把这一格登记成 1（占用） |
| `sall $12,%ecx ; addl LOW_MEM` | 剩余扫描数 × 4KB + 1MB = 这页的**物理地址** |
| `rep ; stosl`（ecx=1024） | 把这 4096 字节**全部清零**——上个住户的痕迹不能留给下家 |

函数开头的注释很俏皮："Get physical address of first (actually last :-)
free page"——说是找第一页，其实从**高地址往低地址**找（第 60 行）。
**返回值是物理地址**；谁领了页、挂到哪个线性地址，是调用者的事。

表格里没说的三处机关：

- **`movb $1,1(%%edi)` 的加一**：`scasb`（`std` 置 DF=1 后倒扫）命中后 edi
  已惯性多退一格，`1(%%edi)` 正好挪回目标格写成 1（占用）；
- **eax 一物两用**：装 0 进去（要找的值），没找到带着 0 返回——"没页了"；
  找到则换成页框物理地址返回，调用方判 0 即可；
- **`invalidate()` 宏**（第 39~40 行）：`__asm__("movl %%eax,%%cr3"::"a" (0))`
  往 CR3 重写页目录基址，CPU 见 CR3 变了就把 TLB 全部作废——7.3.2 起凡改
  页表必喊它，**改页表必须冲 TLB**；现代内核封装成 `flush_tlb()` 一族。

**还地皮：free_page()**（第 89 行）。三行核心（实际函数里 addr 先做 `-= LOW_MEM; >>= 12` 换算成格柜编号，另有 `HIGH_MEMORY` 越界检查）：

```c
if (addr < LOW_MEM) return;          /* 1MB 以下根本不在登记簿上 */
if (mem_map[addr]--) return;         /* 计数减一；原来非 0（还有人用），到此为止 */
mem_map[addr]=0;                     /* 原来就是 0：还了个空格子 */
panic("trying to free free page");   /* 登记簿和事实对不上：panic 抓 bug */
```

一个字节计数器就撑起了整个物理页管理。没有链表、没有位图、没有伙伴系统——
3840 个格子，一行一个登记项，够用了。

### 7.3.2 源码导读二：fork 与写时复制——谁先写，谁复印

第 4 章讲过：fork 出的孩子是父亲的复印件（`*p = *current`）。当时有一句
"复印"打了引号——**内存这一项，0.11 偷懒偷得极其聪明**。

想象一对双胞胎共用一本作业本，规矩是"**只能看，不能写**"；谁想先写，
就得先去复印一本，在复印件上随便写，原作业本留给对方。这就是
**写时复制（Copy-On-Write, COW）**。落在代码上分两幕。

**第一幕：fork 时只复印"图纸"，并贴上"只读"封条。**
`copy_page_tables()`（memory.c 第 150 行）把父进程的页表逐项抄给子进程。
原样整段贴出（第 150~189 行）：

```c
int copy_page_tables(unsigned long from,unsigned long to,long size)
{
	unsigned long * from_page_table;
	unsigned long * to_page_table;
	unsigned long this_page;
	unsigned long * from_dir, * to_dir;
	unsigned long nr;

	if ((from&0x3fffff) || (to&0x3fffff))
		panic("copy_page_tables called with wrong alignment");
	from_dir = (unsigned long *) ((from>>20) & 0xffc); /* _pg_dir = 0 */
	to_dir = (unsigned long *) ((to>>20) & 0xffc);
	size = ((unsigned) (size+0x3fffff)) >> 22;
	for( ; size-->0 ; from_dir++,to_dir++) {
		if (1 & *to_dir)
			panic("copy_page_tables: already exist");
		if (!(1 & *from_dir))
			continue;
		from_page_table = (unsigned long *) (0xfffff000 & *from_dir);
		if (!(to_page_table = (unsigned long *) get_free_page()))
			return -1;	/* Out of memory, see freeing */
		*to_dir = ((unsigned long) to_page_table) | 7;
		nr = (from==0)?0xA0:1024;
		for ( ; nr-- > 0 ; from_page_table++,to_page_table++) {
			this_page = *from_page_table;
			if (!(1 & this_page))
				continue;
			this_page &= ~2;
			*to_page_table = this_page;
			if (this_page > LOW_MEM) {
				*from_page_table = this_page;
				this_page -= LOW_MEM;
				this_page >>= 12;
				mem_map[this_page]++;
			}
		}
	}
	invalidate();
	return 0;
}
```

逐段拆开：

- 第 169~172 行：子进程的**页表本身**也是新领的一页，挂上目录项同样 `| 7`
  （P/R/W/U/S 全开）；`nr=(from==0)?0xA0:1024`——首次 fork 源是内核空间，
  只抄前 160 项（640KB），函数上方 Linus 的大段注释有交代；
- 第 177 行 **`this_page &= ~2` 就是 COW 的全部机关**：清掉表项的 R/W 开关，
  父子表项（第 178、180 行）从此指向**同一个物理页**、都只读；第 181~183 行
  `mem_map[]++`。

注意 `mem_map[]` 的妙用：共用前计数是 1，共用后是 2——**登记簿顺手当起了
引用计数器**。fork 一个 512MB 的进程，实际复制的是几十张页表（每张管 4MB），
物理页一页没抄。

**第二幕：谁先写，CPU 现场喊"抓贼"。**
父子任何一方第一次写这页时，CPU 查页表发现"只读的页居然要写"——硬件**当场**
触发**页保护异常**，自动跳进内核。异常入口在 `linux-0.11/mm/page.s`
（整个文件只有 40 行，值得全读）：

```asm
_page_fault:                    # 第 14 行起
	...
	movl %cr2,%edx          # cr2 = 闯祸的线性地址（CPU 主动交出来的）
	testl $1,%eax           # 错误码 bit0：这页"在不在"内存里？
	jne 1f
	call _do_no_page        #   不在 → 按需调页（7.3.3）
	jmp 2f
1:	call _do_wp_page        #   在，但只读 → 写时复制
```

同一根异常，两种病因，两个医生。写时复制这条线的处理在 `do_wp_page()`
（memory.c 第 247 行），它转手给 `un_wp_page()`（第 221 行）——后者拿闯祸
地址手工查两次表、用 `0xfffff000 &` 剥出共用的物理页。两个函数原样奉上
（第 221~259 行）：

```c
void un_wp_page(unsigned long * table_entry)
{
	unsigned long old_page,new_page;

	old_page = 0xfffff000 & *table_entry;
	if (old_page >= LOW_MEM && mem_map[MAP_NR(old_page)]==1) {
		*table_entry |= 2;
		invalidate();
		return;
	}
	if (!(new_page=get_free_page()))
		oom();
	if (old_page >= LOW_MEM)
		mem_map[MAP_NR(old_page)]--;
	*table_entry = new_page | 7;
	invalidate();
	copy_page(old_page,new_page);
}	
```

```c
void do_wp_page(unsigned long error_code,unsigned long address)
{
#if 0
/* we cannot do this yet: the estdio library writes to code space */
/* stupid, stupid. I really want the libc.a from GNU */
	if (CODE_SPACE(address))
		do_exit(SIGSEGV);
#endif
	un_wp_page((unsigned long *)
		(((address>>10) & 0xffc) + (0xfffff000 &
		*((unsigned long *) ((address>>20) &0xffc)))));

}
```

`do_wp_page()` 只干一件事：拿闯祸地址手工查两次表（`>>20`/`>>10` 后 `&0xffc`，
同 7.3.5），把**指向那枚页表项的指针**递给 `un_wp_page()`——第 225 行
`0xfffff000 &` 从表项剥出共用的物理页（只要高 20 位页框号）。

注意那个容易忽略的分支：`mem_map == 1` 时**根本不复制**——既然没别人共用，
多半是页表上的只读封条还没来得及撕（比如对方已退出），把 R/W 位补上就完事。
真正的"复印一页"只发生在计数大于 1 时。整个流程串起来：

```
 fork：copy_page_tables()        运行：谁先写这页
   父页表 ──复制──► 子页表          CPU 发现"只读页要写"
   （同一物理页，都置只读）   ──►     页保护异常 → page.s
   mem_map[该页]++                    └► do_wp_page() (247)
                                        └► un_wp_page() (221)
                                            共用计数 > 1：复印一页给自己
                                            共用计数 = 1：撕掉只读封条即可
```

**COW 赢三次**：

1. **fork 快**：不复制内存，只抄页表——几百张 4KB 的表替代几百 MB 的数据；
2. **省内存**：父子不写的页（环境变量、还没跑到的代码、大片没动的数据）
   永远共用一份；
3. **语义正确**：每个进程照样以为自己独占全部内存，**一行程序都不用改**——
   这是它比"让程序员手动声明共享"高明的地方。隔离的假象完整保留，
   成本却在真写入时才发生。

### 7.3.3 源码导读三：do_no_page()——页还没到？现场去搬

`page.s` 的另一个分支管"页根本不在内存"的情况，处理函数是 `do_no_page()`
（memory.c 第 365 行）。什么场景会走到这里？**程序第一次访问某段地址**——
比如刚 exec 完，代码一页都还没装进来，CPU 取第一条指令就踩了空。

第 4 章 4.3.6 讲 exec 时说过"0.11 把程序一次性读入内存"——这里要为 0.11
平反一下：它其实已经会**按需调页（demand paging）**。memory.c 开头第 8 行
留着 Linus 的日记："demand-loading started 01.12.91"——这功能正是 1991 年
12 月 1 日写的。exec 只装了参数和环境变量那几页，代码和数据**等第一次访问
才从文件里搬**。`do_no_page()` 原样整段贴出（第 365~397 行）：

```c
void do_no_page(unsigned long error_code,unsigned long address)
{
	int nr[4];
	unsigned long tmp;
	unsigned long page;
	int block,i;

	address &= 0xfffff000;
	tmp = address - current->start_code;
	if (!current->executable || tmp >= current->end_data) {
		get_empty_page(address);
		return;
	}
	if (share_page(tmp))
		return;
	if (!(page = get_free_page()))
		oom();
/* remember that 1 block is used for header */
	block = 1 + tmp/BLOCK_SIZE;
	for (i=0 ; i<4 ; block++,i++)
		nr[i] = bmap(current->executable,block);
	bread_page(page,current->executable->i_dev,nr);
	i = tmp + 4096 - current->end_data;
	tmp = page + 4096;
	while (i-- > 0) {
		tmp--;
		*(char *)tmp = 0;
	}
	if (put_page(page,address))
		return;
	free_page(page);
	oom();
}
```

三步：**算偏移 → 从可执行文件读一页 → 挂进页表**。中间还夹了个
`share_page()`：两个进程跑同一个程序时（比如同时开 30 个 shell），已装入的
代码页直接共享，每人页表里放一个只读项、登记簿 +1——第 12~19 行的注释里
Linus 得意地记录了测试结果："跑 30 个 /bin/sh，旧内核 6MB 内存根本不够，
现在没问题"。

看清楚顺序：**先 `share_page()` 后读盘**（第 378~379 行在第 380 行领新页
之前）——共享成了连磁盘都不用碰。共享页也不是后来补的：第 13~14 行日志
"shared pages started 02.12.91"，即按需调页写完的第二天（欧式"日.月.年"）。

**如实说明 0.11 的极限**：它能"按需装进来"，却**没有"换出去"**——没有
swap 交换分区，没有 LRU 淘汰。内存真的耗尽时只有一个粗暴的出口：`oom()`
（memory.c 第 33 行），打印一行 "out of memory" 然后把当前进程 do_exit 掉。
"内存比 16MB 大的程序跑不动"在 0.11 是常态。换页要等到现代内核：
打开 `linux-2.6.35/mm/`，74 个文件里 `vmscan.c`（扫描冷页逐出）、
`swap.c`/`swapfile.c`（交换分区管理）、`page_alloc.c`（复杂的页分配器）——
"地不够了把闲置家具搬进仓库"这件事，0.11 想都没想，现代内核把它做成了
一门大学问。核心思想却没变：**一切从 mem_map 这排格子开始**。

### 7.3.4 页表项里的六个开关（P/R/W/U/A/D）

7.2.3 说页表"顺带记下权限"，7.3 的代码里满眼 `| 7`、`& 1`、`&= ~2`。每个页表项都是 32 位：**高 20 位页框号 + 低 12 位硬件开关**（bit0 P、bit1 R/W、bit2 U/S、bit3~4 缓存策略、bit5 A、bit6 D）：

| 位 | 开关 | =0 意味着 | =1 意味着 | 0.11 里的真实用法（行号已核对） |
|---|---|---|---|---|
| 0 | **P**（存在） | 页不在内存，访问即触发**缺页异常** | 在内存 | 满眼都是：`put_page` 第 208 行 `if ((*page_table)&1)` 判页表在不在；page.s 第 28 行 `testl $1,%eax` 按它分诊 |
| 1 | **R/W**（读写） | **只读**，写即触发保护异常 | 可写 | COW 命根子：`copy_page_tables` 第 177 行 `&= ~2` 置只读、`un_wp_page` 第 227 行 `|= 2` 恢复 |
| 2 | **U/S**（特权级） | 仅内核态可访问 | 用户程序也可访问 | 用户页必开：`put_page` 第 216 行 `page_table[(address>>12) & 0x3ff] = page \| 7` |
| 5 | **A**（访问过） | 上次清零后没用过 | CPU 用它完成一次翻译就硬件自动置 1 | 0.11 从未检查、从未清零 |
| 6 | **D**（脏） | 装入后没写过 | 被写过（硬件自动置 1） | 0.11 只查过一次：`try_to_share` 第 311 行 `(phys_addr & 0x41)!=0x01`，只肯共享"干净且存在"的页 |

**`| 7` = 0b111**：P、R/W、U/S 三开关一次全开——用户页要能被用户态读写，
缺一不可；`put_page` 第 213 行、`un_wp_page` 第 235 行、head.s `pg0+7` 同款。

**A/D 的现代使命**：换页淘汰看 **A**（A=0 的冷页优先请出去），回写看 **D**
（D=0 直接丢弃，D=1 才写回磁盘）——0.11 只装不换，基本用不上。

**硬件查表如何逐位检查**：MMU 查页目录项先看 P——不在，立即抛出**缺页异常**
（14 号中断，page.s 入口）；在，再核对 U/S 是否放行当前特权级、R/W 是否放行
这次读/写，页表项同样再过一遍。任何一关不过，抛的都是同一个异常，差别在
**错误码**（bit0=P、bit1=W、bit2=U）：page.s 的 `testl $1,%eax` 查的正是
bit0，据此分诊给 `do_no_page()` 或 `do_wp_page()`。实验 7-4 的 Segmentation
fault，就是"几道关都没过、内核确认无救"后的最终判决。

### 7.3.5 一个地址的完整翻译之旅

概念（7.2）与代码（7.3.1~7.3.4）都见过了，把一根真实地址从头走到尾。练习
7.2 请你手算 `0x00401234`（落在 head.s 恒等映射区，可直接复核）；正文换个
更"野"的 **0x12345678**——**进程 4** 数据段里的地址，必须真查表才能落地。

**① 段转换**：进程 4 的 LDT 数据段基址 = 4 × 64MB = 0x10000000（fork.c
第 52 行），逻辑地址（段内偏移）0x02345678 加基址得线性地址 `0x12345678`。
**② 拆成 10+10+12、查两轮表**（页目录固定在物理 0）：

```
线性地址 0x12345678 = 0001001000 | 1101000101 | 011001111000
                      目录号 72      页表号 837     偏移 0x678
   │ ③ 查页目录：第 72 项 @物理 72×4=0x120 = 0x00C00007
   ▼
页表 @物理 0x00C00000 （低 12 位 007：P/R/W/U/S 全开，见 7.3.4）
   │ ④ 查页表：第 837 项 @物理 0x00C00000+837×4=0x00C00D14 = 0x00123007
   ▼
页框 0x00123000 （同样 |7；若是 fork 后没人写过的 COW 页，R/W 关着，以 …5 收尾）
   │ ⑤ 基址 + 偏移
   ▼
物理地址 0x00123000 + 0x678 = 0x00123678 ──► 内存条
```

三句回味。中途可能"进站维修"：第 72 项 P=0 → page.s 接住缺页异常，
`do_no_page()` 现场建房（7.3.3）；P=1 但这次是写、R/W=0 → `do_wp_page()`
复印（7.3.2）——两轮查表逐关检查的，就是 7.3.4 那排开关；两轮查表 = 多两趟
读内存，这正是 TLB 存在的理由、改页表必须 `invalidate()` 的原因。中间那些
页表位置、页框号是运行时账本，拆地址的方法是铁打的——`(from>>20)&0xffc`
（`copy_page_tables`）、`(address>>10)&0xffc`（`do_wp_page`）就是原貌。
合上书，把练习 7.2 亲手走一遍。

## 7.4 用户态的 malloc：你要的内存，内核给的是"期票"

C 程序员天天调 `malloc(1024)`，这 1KB 是从哪儿来的？分三个层次看。

**0.11 用户程序这一层**：运行库的 `malloc` 底下是 `sbrk`，最终走系统调用
`sys_brk`（`linux-0.11/kernel/sys.c` 第 168 行）：

```c
int sys_brk(unsigned long end_data_seg)
{
	if (end_data_seg >= current->end_code &&
	    end_data_seg < current->start_stack - 16384)
		current->brk = end_data_seg;   /* 只是改一个数字！ */
	return current->brk;
}
```

看清楚：**内核什么内存都没分配，只把进程档案里的 `brk` 字段改成了新值**——
堆的"天花板"抬高了几 KB。真正的物理页，要等你第一次访问那片地址、CPU 触发
页不在异常、`do_no_page()` 上场时才到手。`malloc` 返回的指针是一张**期票**：
"这地址归你了"，至于地——等你真去踩，现场平整。

（顺带澄清一个容易张冠李戴的点：0.11 源码里也有个 `lib/malloc.c`，但那是
**内核自己用**的桶式分配器——`bucket_dir[]` 按 16、32、64……4096 字节九个
档位（第 77~87 行）把整页切碎重复利用，最大只能分 4KB，跟用户程序的
malloc 不是一回事。内核分配物理内存靠的还是 7.3.1 的 `get_free_page()`。）

**现代 glibc 这一层**：思路一脉相承——小块从堆里切（brk），大块直接
`mmap` 一段新地址；库内部还按尺寸分箱管理，减少碎片。**但"先给地址、后给
物理页"的两步戏码完全没变**。

这给本章最后一个伏笔：如果 malloc 的内存在第一次写入前不占物理内存，
那我们能否**亲眼看到**"写多少、占多少"？下面实验 7-3 就是干这个的。

## 7.5 动手实验

以下程序在 macOS 和 Linux 上都可直接编译运行。老规矩：每一步先**预测**，
再运行验证。

### 实验 7-1：你的程序住在哪里？——打印各区域的地址

```c
/* exp7-1-addr.c */
#include <stdio.h>
#include <stdlib.h>

int g_init = 42;                  /* 已初始化全局：数据段 */
int g_zero;                       /* 未初始化全局：bss 段 */
const char *str = "hello, mm";    /* 字符串常量：通常在只读数据区 */

int main(void)
{
    static int s_static = 7;      /* 静态局部变量：也在数据段 */
    int stack_var = 1;            /* 局部变量：栈 */
    int arr[4] = {0};             /* 数组：还是栈 */
    char *p1, *p2;

    p1 = malloc(1024);            /* 堆 */
    p2 = malloc(4096);            /* 再来一块，看堆往哪边长 */

    printf("代码段      main        = %p\n", (void *)main);
    printf("只读数据    字符串常量   = %p\n", (const void *)str);
    printf("数据段      g_init      = %p\n", (void *)&g_init);
    printf("数据段      s_static    = %p\n", (void *)&s_static);
    printf("bss         g_zero      = %p\n", (void *)&g_zero);
    printf("堆          malloc 1K   = %p\n", (void *)p1);
    printf("堆          malloc 4K   = %p\n", (void *)p2);
    printf("栈          stack_var   = %p\n", (void *)&stack_var);
    printf("栈          arr         = %p\n", (void *)arr);

    free(p1);
    free(p2);
    return 0;
}
```

```bash
gcc exp7-1-addr.c -o addr && ./addr
```

把九个地址从小到大排序，应该能拼出经典布局（栈向下长、堆向上长，
中间隔着一大片还没用的空间）：

```
高地址  ┌──────────────────┐
        │ 栈 ↓  stack_var, arr │  ← 这些地址最大
        │     （空闲空洞）      │
        │ 堆 ↑  p2, p1         │
        ├──────────────────┤
        │ bss      g_zero      │
        │ 数据段   g_init, s_static
        │ 只读数据 字符串常量    │
        │ 代码段   main        │  ← 地址最小
低地址  └──────────────────┘
```

再运行一次：两次地址可能**不一样**——这是地址空间随机化（ASLR），安全
特性，让攻击者猜不准布局。macOS 默认开 PIE，代码段地址每次都变；Linux
也是。同一进程内的**相对位置**才是稳定的观察对象。

### 实验 7-2：/proc/self/maps——内核亲自公布的地图

Linux 把每个进程的地址空间布局登记在 `/proc/<pid>/maps` 里。让实验 7-1
的程序多睡一会儿（把 `return 0;` 前加 `sleep(30);` 重新编译），另开终端：

```bash
# Linux：
cat /proc/$(pgrep -f exp7-1)/maps
```

你会看到按地址排列的每一段，类似：

```
00400000-00401000 r--p 00000000 08:01 ...   /home/me/exp7-1   ← 只读：ELF 头
00401000-00402000 r-xp 00001000 08:01 ...   /home/me/exp7-1   ← 代码段
00402000-00403000 r--p 00002000 08:01 ...   /home/me/exp7-1
00403000-00404000 rw-p 00003000 08:01 ...   /home/me/exp7-1   ← 数据段
...（堆、各种库映射）...
7ffd0e3a0000-7ffd0e3c1000 rw-p 00000000 00:00 0               [stack]
```

重点看**权限列** `rwxp` 四个字母：`r` 可读、`w` 可写、`x` 可执行、`p` 私有。
代码段是 **r-x**：能读能执行、**不可写**——想在代码段写东西？页表先不答应，
这就是 7.1 难题一"隔离"活生生的样子。macOS 没有这个文件，可用
`vmmap <pid>`（自带命令）看类似内容，权限列是 `r-x/rw-` 风格。

### 实验 7-3：亲眼看见写时复制——fork 512MB

```c
/* exp7-3-cow.c */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

#define SIZE (512UL * 1024 * 1024)    /* 512MB */

int main(void)
{
    char *buf = malloc(SIZE);
    size_t i;
    pid_t pid;

    if (!buf) { perror("malloc"); return 1; }

    printf("[父 %d] 逐页写入 %zuMB（这一步真正占物理内存）\n",
           getpid(), SIZE / 1024 / 1024);
    for (i = 0; i < SIZE; i += 4096)
        buf[i] = 1;        /* 每页摸一下：否则 malloc 是张期票，见 7.4 */

    pid = fork();          /* 此刻 COW 生效：512MB 物理页一页没抄 */
    if (pid == 0) {
        printf("[子 %d] 睡 2 秒，然后只写前一半……\n", getpid());
        sleep(2);
        memset(buf, 2, SIZE / 2);   /* 写 256MB → 这一半触发复制 */
        printf("[子] 写完前一半，长眠 20 秒供你观察\n");
        sleep(20);
        return 0;
    }
    printf("[父 %d] fork 完了，我 20 秒内绝不动 buf——盯着内存看！\n",
           getpid());
    sleep(20);
    wait(NULL);
    return 0;
}
```

```bash
gcc exp7-3-cow.c -o cow && ./cow &
# 程序跑着的 20 多秒里，另开终端反复执行（2 秒一次）：
ps aux | grep '[c]ow' | awk '{printf "pid=%s  rss=%d MB\n", $2, $6/1024}'
```

观察三个时刻，对照预测：

1. **memset 完、fork 之前**：父进程 RSS 约 512MB；
2. **fork 刚完成**：子进程 RSS 很小（实测约 1MB）——512MB 的页**一页没抄**，
   父子共用同一批物理页。有的内核此时会把共享页也计入子进程 RSS（显示约
   512MB），但看系统总内存（Linux `free -h` 的 used），**几乎没有增加**：
   RSS 统计的是"进程地址空间里驻留的页"，共享的页两边各计一份，物理内存
   只有一份；
3. **子进程写完前一半**：子进程 RSS 涨到约 **256MB**——只有被写的那一半
   真的复制了——而父进程 RSS 纹丝不动。

如果 fork 是"老实复制"，第 2 步系统就得凭空多出 512MB。它没有——
这就是 `copy_page_tables()` 只抄页表 + `un_wp_page()` 按需复印的现场演示。
macOS 上 `ps` 的 RSS 含义类似但口径略有差别，可用"活动监视器"的"内存"列
或 `footprint` 命令观察同样三个时刻。

### 实验 7-4：亲手制造一次"Segmentation fault"

```c
/* exp7-4-segv.c */
#include <stdio.h>

int main(void)
{
    int *p = 0;          /* 空指针 */
    printf("马上就要闯祸了……\n");
    *p = 42;             /* 往 0 号地址写入！ */
    printf("这行永远走不到\n");   /* 死后世界 */
    return 0;
}
```

```bash
gcc exp7-4-segv.c -o segv && ./segv
echo $?        # 看退出码
```

shell 会打印 **Segmentation fault**（段错误），程序死于 `*p = 42` 这一行。
它和 7.3.2 的 COW 是**同一个异常家族**：CPU 发现这次访问过不了页表的检查
（0 号页要么"不在内存"要么"不可写"），触发页异常进内核；内核一看这不是
COW 的剧本（0 地址根本没人给你映射），是真正的非法访问——现代内核走
`do_page_fault()` 确认无救后给进程发 SIGSEGV 信号，0.11 里段的界限和页保护
同样会把这种访问拦下。**"Segmentation fault" 不是玄学咒语，是页保护机制
按设计执行了死刑。** Linux 上还能在 `sudo dmesg | tail` 里看到一行
`segv[123]: segfault at 0 ip ...`——at 0 就是闯祸地址，内核法医报告。

## 7.6 常见误区

**误区一："指针里存的地址就是内存条上的物理地址。"**
你打印的任何指针都是**逻辑地址的偏移**，经过分段、分页两道翻译才落到物理
内存。0.11 里每个 exec 后的程序都"以为"自己的代码从 0 开始——同一台机器上
几十个进程引用同一个指针值，背后却是几十块不同的物理内存。地址是"虚拟的"，
翻译才是"真的"。

**误区二："malloc 完，这块内存就是我的了，物理内存立刻变少。"**
malloc 只改了堆的天花板（0.11 里 `sys_brk` 只改 `current->brk` 一个数字），
物理页要等第一次**写入**才通过缺页机制分配。实验 7-3 第 1 步"逐页摸一遍"
就是为了把期票兑换成真金白银。

**误区三："逻辑地址、线性地址、物理地址是一回事的不同叫法。"**
0.11 里它们是三样东西：程序看到的是段内偏移，分段加上 64MB 基址得线性
地址，分页查表得物理地址。混用术语会让你在 head.s、fork.c、memory.c 之间
迷路——比如"64MB 地址空间"说的是**线性**配额，16MB 说的才是**物理**家底。

**误区四："fork 会把父进程的内存整个复制一份，所以大进程 fork 很危险。"**
0.11 起就用写时复制：fork 只抄页表并把页置只读，谁先写谁才复印那一页，
代价从"O(全部内存)"降到"O(实际写入)"。更早的老式 Unix 确实老实复制，
大进程 fork 又慢又费；COW 一出，fork 快、内存省、语义不变，三头全赢
（现代内核还进一步用 `CLONE_` 家族把"复制哪些"做成了选项，见第 4 章 4.6）。

## 练习题

**7.1（概念）** 0.11 最多 64 个进程，每个进程 64MB 线性空间，合计 4GB；
可物理内存只有 16MB。用"超卖"的语言解释：为什么这不叫欺骗？
什么情况下超卖会"爆仓"？（提示：爆仓 = `get_free_page()` 返回 0，
然后 7.3.3 末尾那个函数会出场。）

**7.2（手算）** 线性地址 `0x00401234` 走二级页表：目录号、页表号、页内偏移
各是多少？若它落在 0.11 启动时 head.s 建的恒等映射里，对应的物理地址是
多少？（提示：目录号 = 地址 >> 22；页表号 = (地址 >> 12) & 0x3ff；
偏移 = 地址 & 0xfff。恒等映射就是"线性地址即物理地址"，算完可用
4MB + 页表号 × 4KB + 偏移 复核一遍。）

**7.3（读码）** `get_free_page()`（memory.c 第 63 行）为什么从登记簿**末尾**
往前扫，而不是从头扫？再看 `mem_init()`（第 399 行）：它先把 3840 格全部
置成 USED、再释放内核之后那一段——如果不先全置 USED 会漏掉哪段内存？
（提示：`LOW_MEM` 到 `start_mem` 之间住着谁。）

**7.4（读码）** `copy_page_tables()` 里 `this_page &= ~2`（第 177 行）清的是
页表项哪一位？如果删掉这一行，fork 后子进程立刻改写共享数据，会发生什么？
再想一步：为什么除了给子进程的表项，**父进程**的表项也要改成只读
（第 180 行）？只改一边不行吗？

**7.5（实验 + 思考）** 把实验 7-3 改成子进程把 512MB **全部**写一遍：
系统 used 会涨多少？如果父子**都不写**呢？再读 `un_wp_page()`（memory.c
第 221 行）：当 `mem_map[旧页]` 已经等于 1 时它做了什么——"写时复制"这时
复制了吗？由此总结：COW 的真正开销跟什么成正比，跟 fork 时进程多大无关？

**7.6（对照思考）** 0.11 的程序一旦整体大于 16MB 物理内存就跑不动，只能
`oom()`；现代 Linux 却能同时跑十几个占几 GB 的程序。缺的那块拼图叫什么名字，
它把 7.3.3 的"按需调页"推广到了什么方向？（提示：能"装进来"也要能
"搬出去"；去 `linux-2.6.35/mm/` 里找 `swap` 和 `vmscan` 开头的文件。）

## 本章小结

1. 内存管理两大任务：**保护（隔离）**与**复用（超卖）**——16MB 物理内存敢服务 64 × 64MB 的账面地址空间。
2. 地址两道翻译：**分段**（逻辑 + 段基址 = 线性，0.11 每进程 64MB，管隔离）→ **分页**（查二级页表得物理，管复用）。
3. 线性地址 = **10 位目录号 + 10 位页表号 + 12 位偏移**；页目录在物理 0，一个目录项管 4MB——`copy_page_tables()` 因此要求 4MB 对齐。
4. `mem_map[]`：3840 个字节记 15MB 的账，一字节兼任占用标志与引用计数；`get_free_page()` 高往低扫、清零、返回物理地址，找不到就返回 0。
5. 页表项低 12 位是开关：**P/R/W/U/S** 硬件逐位检查、过不去就抛异常；**A/D** 是现代内核换页与回写的依据，0.11 基本没用。
6. **COW**：fork 只抄页表并置只读（`&= ~2`），谁先写谁触发页保护异常，`un_wp_page()` 计数大于 1 才真复印，等于 1 时撕封条直接放行。
7. `do_no_page()` 按需调页：先 `share_page()` 再读文件；malloc 是期票，第一次访问才兑现物理内存。
8. 改页表必须 `invalidate()` 冲 TLB；0.11 只能"装进来"不能"换出去"，换页是现代 `vmscan.c`/`swap.c` 的活，账本思想与 mem_map 一脉相承。
