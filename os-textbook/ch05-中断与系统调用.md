# 第 5 章 中断与系统调用

> **学习目标**
> 1. 能说清用户态/内核态为什么存在，CPU 靠什么区分它们；
> 2. 能完整复述一次系统调用的旅程：库函数 → `int 0x80` → IDT → `system_call` →
>    `sys_call_table` → `sys_write` → 返回值带回用户态；
> 3. 看懂 `linux-0.11/kernel/system_call.s` 最核心的几十行汇编；
> 4. 体会函数指针表"一张表管全部服务"的精妙；
> 5. 知道时钟中断如何每 10ms 给调度器"上一次发条"（第 6 章主角登场前传）；
> 6. 会用 `strace` 和 `syscall()` 在自己的电脑上亲眼观察系统调用。

## 5.1 从一个问题开始：一行 printf，凭什么能让屏幕亮起来？

在 C 语言入门课里，你写过无数次这样的程序：

```c
#include <stdio.h>
int main(void)
{
    printf("hello\n");
    return 0;
}
```

一行 `printf`，屏幕上就出现了字符。可是慢着——**屏幕是硬件，内存里根本没有
一行"C 语句"能点亮它**。要把一个字符画到屏幕上，得往显卡的显存里写数据、
操作显卡的寄存器（`in`/`out` 指令）。这些活儿谁干的？

你可能会想：那 `printf` 自己去干吧。**干不了**。第 2 章 2.5 节说过，CPU 有
权限等级：你的程序运行在**用户态（Ring 3）**，`in`/`out` 这类特权指令、
直接写显存的越权访问，统统会被 CPU 当场拦下（硬件异常）。这是故意设计的：
要是每家住户都能自己接线改电路，一户短路，整栋楼完蛋——一个写坏指针的程序
可能顺手把显卡刷成雪花，甚至把别的程序内存当显存写。

所以规则只能是：**应用程序自己不碰硬件，一切硬件服务都要"过窗口"**——
委托一个常驻内存、权限更高的程序代办。这个程序就是**内核**（第 1 章的物业），
这个"窗口"就是本章的主角：**系统调用（system call）**。

`printf` 的真实身份是**库函数**：它先在用户态把你给的格式串加工成最终字符
（`%d` 变成数字……这些纯计算不需要特权），最后调用系统调用 `write`，把
"往 1 号文件（标准输出）写这 14 个字节"的请求递进窗口。窗口里面，内核的
终端驱动（第 10 章）把字符送进显存——屏幕这才亮了。

本章我们就在 linux-0.11 里把这条"求助通道"从窗口外走到窗口里，每一站都
打开真实源码指给你看。全程用一个好记的比喻：**去医院看病**。

## 5.2 核心概念：两个世界，两扇门

### 5.2.1 用户态与内核态：CPU 的两种"工牌"

第 2 章用"门禁卡"比喻过保护模式，现在把权限这半边讲精确。x86 的保护模式
有 4 个特权级（Ring 0~3），Linux 只用两个：

| | 内核态（Ring 0） | 用户态（Ring 3） |
|---|---|---|
| 谁在用 | 内核代码 | 你的程序、gcc、bash…… |
| 特权指令（`lidt`、`in`/`out`、改页表等） | **可以** | 一律被 CPU 拦下 |
| 能访问的内存 | 全部 | 只限分配给自己的那几段 |
| 0.11 里的代码段选择子 | `0x08`（低 2 位 = 0） | `0x0f`（低 2 位 = 3） |

CPU 怎么知道当前是哪个态？**看 cs 寄存器选择子的低 2 位**（叫 CPL，当前
特权级）：00 就是内核态，11 就是用户态。上面表格里那两个数你会在本章源码
里反复见到——`0x08` 与 `0x0f` 差的正是这两个比特。

要强调的是：**态是 CPU 的属性，不是程序的属性**。同一段代码，跑到内核
那几行时 CPU 就是内核态，返回你的 main() 时又切回用户态。5.3 节你会看到
这次"换工牌"是 `int` 指令自动完成的，连栈都会顺手换成内核自己的栈。

### 5.2.2 进内核的两扇门：硬件中断与软件中断

第 2 章 2.6 节讲过中断的基本流程（门铃响 → 压栈断点 → 查 IDT → 执行处理
程序 → `iret` 回来）。这里换个视角：**中断是用户态程序进入内核态的两扇门**。

- **门一：硬件中断**——设备"喊人"，CPU 被动进内核。时钟每 10ms 响一次
  （5.5 节），你每敲一个键响一次（5.6 节）。这不是程序请求的，是事件驱动。
- **门二：软件中断**——程序**主动**执行 `int N` 指令，把门敲开。0.11 约定
  系统调用统一走 `int 0x80`。0.11 启动时，内核就在 IDT 的第 0x80 项登记了
  系统调用的总入口（`kernel/sched.c` 第 411 行：

  ```c
  set_system_gate(0x80,&system_call);
  ```

  `set_system_gate` 与第 2 章 `head.s` 里填 IDT 是一回事，只是这类"门"特别
  开放了权限：允许特权级 3 的代码来敲；为何时钟的门不开放，5.10 节用 DPL
  拆解明白）。

两扇门查的都是同一张 IDT（256 项，第 2 章讲过），区别只在于**谁按的门铃**。
进了门，都在内核态干活，干完 `iret` 回去。

注意区分两个容易搞混的号码，本章后面会反复用到：

| | 中断号 | 系统调用号 |
|---|---|---|
| 例子 | `0x80` | `4`（write） |
| 作用 | 查 IDT，决定"从哪个门进内核" | 查 sys_call_table，决定"内核里哪个函数接活" |
| 谁登记 | 内核启动时填 IDT（sched.c 第 411 行） | `include/unistd.h` 里 `#define __NR_write 4` |

一个门牌，一张业务号：**所有 72 种系统调用共用 0x80 这扇门，进门后再靠
系统调用号分流**。就像医院只有一个大门，挂什么科靠号牌决定。

## 5.3 源码导读：一次 write() 的完整旅程（本章核心）

目标：追完 `write(1, "hello\n", 6)` 从用户态到内核再回来的每一步。

### 5.3.1 出发点：lib/write.c，全文件只有一行

先看 0.11 里"C 库的 write 函数"的源码——它自己也是"一行"：

```c
/* linux-0.11/lib/write.c */
#define __LIBRARY__
#include <unistd.h>

_syscall3(int,write,int,fd,const char *,buf,off_t,count)
```

`_syscall3` 不是函数调用，是**宏**（附录 B 话题）。它会把这一行展开成一个
真正的 `write()` 函数定义。

### 5.3.2 _syscall3 宏：把 write() 展开成 int $0x80

宏定义在 `include/unistd.h` 第 172~183 行（摘录，去掉了换行符）：

```c
#define _syscall3(type,name,atype,a,btype,b,ctype,c) \
type name(atype a,btype b,ctype c) \
{ \
    long __res; \
    __asm__ volatile ("int $0x80" \
        : "=a" (__res) \
        : "0" (__NR_##name),"b" ((long)(a)),"c" ((long)(b)),"d" ((long)(c))); \
    if (__res>=0) \
        return (type) __res; \
    errno=-__res; \
    return -1; \
}
```

这段内嵌汇编（gcc 的扩展语法，寄存器约定比语法本身重要）说的是：

1. 调用号放进 **eax**：`__NR_##name` 把名字拼成 `__NR_write`——unistd.h
   第 64 行定义它等于 4；
2. 三个参数依次放进 **ebx、ecx、edx**（0.11 的约定：参数最多 3 个，再多
   就得打包成结构体传指针）；
3. 执行 `int $0x80`——敲响内核的门；
4. 返回值从 **eax** 接回 `__res`：非负当成功返回；负数说明内核报了错，
   取相反数存进全局变量 `errno`，函数返回 -1。**这正是经典 C 库"失败返回
   -1 + errno"的来历**——规矩是内核定的。

去医院：挂号处给你编号（调用号进 eax），把病历材料分三份递进去
（ebx/ecx/edx），然后坐等报告单（eax 回来）。

### 5.3.3 全旅程流程图

```
 用户态（Ring 3）                              内核态（Ring 0）
 ─────────────────                            ─────────────────────
 printf("hello\n")                             （系统调用总入口）
    │ 格式化在用户态完成                          ▲
    ▼                                          │
 write(1, buf, 6)   ← lib/write.c 一行          │
    │ 宏 _syscall3 展开                          │
    ▼                                          │
 eax = 4   ebx = 1   ecx = buf   edx = 6        │
    │                                           │
 int $0x80 ──────────────────────────────────► CPU 查 IDT 第 0x80 项
 （门被敲响；CPU 换到内核栈，                    │ 得到入口地址 system_call
   特权级 3 → 0）                                ▼
                                   kernel/system_call.s 第 80 行
                                               │ ① 调用号合法？(≥72 拒收)
                                               ▼
                                   call sys_call_table(,%eax,4)  第 94 行
                                               │ ② 4 号窗口 = sys_write
                                               ▼
                                   fs/read_write.c 第 83 行 sys_write()
                                               │ ③ 干活：找到 1 号文件
                                               │   对应的终端，把字节送下去
                                               ▼
                                   返回值放 eax；顺手看看要不要调度
                                               │
 write() 返回 6 ◄────────────── iret ──────────┘ ④ 弹栈、换回用户态
    │
    ▼
 printf 返回，屏幕上已经有了 hello
```

下面把内核里这几站逐个打开。

### 5.3.4 内核入口：system_call（system_call.s 第 80 行起）

`int 0x80` 之后 CPU 落进的第一行代码，在 `kernel/system_call.s` 第 80 行
（汇编里函数名前的下划线是当年 gcc 的命名约定，`_system_call` 就是 C 里的
`system_call`）。这次把原文一次贴够——第 78~105 行，直到返程的门口：

```asm
	jmp _schedule
.align 2
_system_call:
	cmpl $nr_system_calls-1,%eax
	ja bad_sys_call
	push %ds
	push %es
	push %fs
	pushl %edx
	pushl %ecx		# push %ebx,%ecx,%edx as parameters
	pushl %ebx		# to the system call
	movl $0x10,%edx		# set up ds,es to kernel space
	mov %dx,%ds
	mov %dx,%es
	movl $0x17,%edx		# fs points to local data space
	mov %dx,%fs
	call _sys_call_table(,%eax,4)
	pushl %eax
	movl _current,%eax
	cmpl $0,state(%eax)		# state
	jne reschedule
	cmpl $0,counter(%eax)		# counter
	je reschedule
ret_from_sys_call:
	movl _current,%eax		# task[0] cannot have signals
	cmpl _task,%eax
	je 3f
	cmpw $0x0f,CS(%esp)		# was old code segment supervisor ?
```

逐站看：

- **第 61 行**有个常量 `nr_system_calls = 72`——0.11 全部系统调用的总数。
  第 81~82 行拿它当保安：`cmpl` 把调用号与上限 71 比较、`ja`（无符号大于
  才跳）构成越界检查——**调用号 ≥ 72 一律拒收**，跳到 `bad_sys_call`
  （第 72~74 行：`movl $-1,%eax` 然后 `iret`——报告单上写个 -1 走人）。
- 第 83~88 行把段寄存器和三个参数寄存器压栈——C 函数按约定从**栈**里取
  参数（第 2 章 2.4 节）。压入顺序 **edx → ecx → ebx** 看似"倒着"，其实
  恰是守规矩：C 函数参数按**从右到左**压栈（cdecl 约定），最右边的 count
  在 edx 里最先压，最后压入的 ebx（=fd）正好停在栈顶——`call` 压入返回
  地址后，C 函数看到的栈自顶向下依次是 fd、buf、count。调用号不用压栈：
  它独占 eax，查表指令直接取用。
- 第 89~93 行换段寄存器：`ds`/`es` 换成 `0x10`（内核数据段），`fs` 换成
  `0x17`（**用户**数据段，注意它低 2 位是 3）。留一个指回用户地址空间的
  窗口，`sys_write` 才能读到用户传来的 buf——不然内核自己都够不着你的内存。

### 5.3.5 服务窗口大屏：sys_call_table

第 94 行那条汇编值得单独讲。`call _sys_call_table(,%eax,4)` 是 x86 的
**比例变址寻址**：跳转目标 = 表基址 + eax × 4。4 是每个表项的字节数
（32 位指针占 4 字节）。换句话说：**这是一次数组下标访问，下标就是系统
调用号，数组元素是函数指针**。

表本体在 `include/linux/sys.h` 第 74~86 行：

```c
fn_ptr sys_call_table[] = { sys_setup, sys_exit, sys_fork, sys_read,
sys_write, sys_open, sys_close, sys_waitpid, ...
sys_setreuid,sys_setregid };
```

- 类型 `fn_ptr` 是"返回 int、参数不限"的函数指针，定义在
  `include/linux/sched.h` 第 38 行：`typedef int (*fn_ptr)();`
- 上面 72 行 `extern` 声明（第 1~72 行）+ 这个 72 项的表，**一项不多一项
  不少**，与 `nr_system_calls = 72` 精确对上。
- 对号入座：`__NR_fork` = 2 → 表第 2 项 `sys_fork`（第 4 章的主角！），`__NR_write`
  = 4 → 表第 4 项 `sys_write`。第 4 章你读过的 `fork()`，当时就是从这里被
  叫到的。

`sys_write` 本体在 `fs/read_write.c` 第 83 行。它先检查 fd 合法、文件是否
可写，然后按文件类型分流：管道走 `write_pipe`，字符设备走 `rw_char`，块
设备走 `block_write`，普通文件走 `file_write`。1 号 fd 对应终端，属于字符
设备——最终由第 10 章的终端驱动把字符写上屏幕。第 9 章我们再回来细读它。

### 5.3.6 返程：返回值、调度检查与 iret

`sys_write` 的返回值留在 eax 里（C 函数的返回值约定就放在 eax）。5.3.4
节的清单已经把返程开头（第 95~105 行）贴在眼前：先 `pushl %eax` 存好
返回值，再取 `_current` 查当前进程的 `state` 和 `counter`——这里藏了个
彩蛋：**系统调用办完事，内核会顺手检查"要不要换人跑"**。`_current` 指向
当前进程的 task_struct（第 4 章），睡下了或时间片用光，就跳 `reschedule`
（第 76~78 行）调第 6 章的主角 `schedule()`——每次系统调用都是一次
"顺便查岗"的机会。

把返程剩下的原文也一次贴全——`system_call.s` 第 106~128 行，从岗哨到
`iret` 一气呵成：

```asm
	jne 3f
	cmpw $0x17,OLDSS(%esp)		# was stack segment = 0x17 ?
	jne 3f
	movl signal(%eax),%ebx
	movl blocked(%eax),%ecx
	notl %ecx
	andl %ebx,%ecx
	bsfl %ecx,%ecx
	je 3f
	btrl %ecx,%ebx
	movl %ebx,signal(%eax)
	incl %ecx
	pushl %ecx
	call _do_signal
	popl %eax
3:	popl %eax
	popl %ebx
	popl %ecx
	popl %edx
	pop %fs
	pop %es
	pop %ds
	iret
```

拼起来看，`system_call` 的返程是个**三岔口**：

1. **该不该换人？**（第 96~100 行）查 `_current` 的 `state` 与 `counter`：
   睡下了或时间片用光，就去 `reschedule`——压入返回地址后 `jmp _schedule`，
   调第 6 章的主角 `schedule()`。核对一个变量名：别的资料里的
   `cmpl $0,_need_resched` 是**后来内核**的写法；0.11 没有这个全局标志，
   直接查 task_struct 的 `state`/`counter` 字段（第 48~49 行的偏移）。
2. **该不该收信号？**（第 101~120 行）三道岗哨：0 号进程不查（注释
   `task[0] cannot have signals`）；`CS(%esp)` 得是 0x0f、`OLDSS(%esp)`
   得是 0x17——刚才跑的得是**用户态**（系统调用必过，这道检查是给共用
   返程的中断留的：时钟可能打断**内核**代码，那种情况不急着收信号）。
   然后 `signal`（待处理位图）与 `blocked`（屏蔽位图）经 `notl + andl`
   合出"待处理且未屏蔽"的信号，`bsfl` 挑出**编号最小**的一个；没有
   （`je 3f`）就走人，有则 `btrl` 清位、信号号压栈、`call _do_signal` 送达。
3. **正常出口**（第 121~128 行的 `3:`）无论走没走信号岔都汇到这里：七个
   寄存器依次弹回，`iret`——CPU 换回用户态的栈和 cs（低 2 位变回 3），
   从 `int $0x80` 下一行接着跑，eax 里是写成功的字节数。清单之后紧接着
   的 `_coprocessor_error`（第 131 行起）是下一个标签：它保存现场后压入
   `ret_from_sys_call` 再跳去自己的例程，办完事同样汇入这条返程——文件
   开头注释 "some of the code is the same" 说的就是这种共用。

把比喻补全：

| 医院 | 内核 |
|---|---|
| 挂号号牌 | 系统调用号（eax，write 是 4） |
| 科室叫号大屏 | `sys_call_table`（72 项） |
| 医生 | `sys_write` 等内核函数 |
| 病历材料 | ebx / ecx / edx 里的参数 |
| 报告单 | eax 里的返回值 |
| 挂了不存在的号 | `bad_sys_call`：报告单写 -1 |

## 5.4 函数指针表的精妙：一张表管全部服务

5.3 里那张 `sys_call_table`，值得停下来欣赏两分钟。先在用户态复刻一个
迷你版（完整可编译）：

```c
/* mini_table.c —— 两人的"医院大屏" */
#include <stdio.h>

int doctor_a(int x) { return x + 1; }   /* 0 号窗口：加一 */
int doctor_b(int x) { return x * 2; }   /* 1 号窗口：翻倍 */

int main(void)
{
    int (*table[2])(int) = { doctor_a, doctor_b };
    int no = 1;                         /* 挂了 1 号 */
    printf("%d\n", table[no](10));      /* 按号叫人：输出 20 */
    return 0;
}
```

`table[no](10)` 就是"按号查表、跳去对应函数"。它比写一串

```c
if (no == 0) doctor_a(10); else if (no == 1) doctor_b(10); ...
```

好在哪？

1. **入口代码永不膨胀**：72 种系统调用，入口处永远只有第 81~94 行那十来行
   汇编；换成 if-else，每加一个服务入口就得长一截。
2. **加服务 = 表尾添一行**：第 13 章大作业"给 0.11 加一个自己的系统调用"，
   核心动作就是往这张表末尾添一个函数名。
3. **数据与逻辑分离**：表就是数据，可以整体搬运、甚至换一张表——第 13 章
   你会见到这种玩法。

内核里这种表不止一张：5.6 节的键盘驱动里还有一张 `key_table`，按扫描码
分派处理函数。附录 B 的"C 语言速查"里对函数指针数组有专门条目，读不透
的地方去那里补。

## 5.5 时钟中断：给调度器上发条

系统调用是程序**主动**敲门；现在看被动的：**时钟中断**——第 6 章调度器
的节拍器，没有它，一个死循环程序就能霸占 CPU 到天荒地老。

0.11 用 8253/8254 定时器芯片（也叫 PIT）：它接的晶振每秒振动 1193180 次，
内核把它设成"每数 LATCH 次就发一个脉冲"。LATCH = 1193180 ÷ HZ，即
1193180 ÷ 100——C 的整数除法把 11931.8 舍成 **11931**，1193180 ÷ 11931 ≈
100，所以**每 10ms 发一次中断（频率 100Hz）**：

```c
/* include/linux/sched.h 第 5 行 */
#define HZ 100

/* kernel/sched.c 第 46 行 */
#define LATCH (1193180/HZ)
```

初始化在 `sched_init()`（sched.c 第 385 行）里，第 406~409 行：

```c
	outb_p(0x36,0x43);		/* binary, mode 3, LSB/MSB, ch 0 */
	outb_p(LATCH & 0xff , 0x40);	/* LSB */
	outb(LATCH >> 8 , 0x40);	/* MSB */
	set_intr_gate(0x20,&timer_interrupt);
```

前三行把 LATCH 写进 8253 的 0x40 端口（"每 11931 个脉冲喊一次"），第四行
在 IDT 第 0x20 项登记处理程序——IRQ0 被映射到中断号 0x20（第 2 章 setup.s
讲过 8259A 的重映射），时钟是 0 号 IRQ，所以是 0x20。

每次脉冲落进 `kernel/system_call.s` 第 176 行的 `_timer_interrupt`（是的，
时钟中断的代码和系统调用挤在同一个文件里，第 7~10 行的注释解释了原因：
它们共用后面那段返回代码）：

```asm
_timer_interrupt:
	...（保存现场，换 ds/es/fs 到内核段，第 177~188 行）
	incl _jiffies                   ! 第 189 行：系统 uptime 加一拍
	movb $0x20,%al		! EOI to interrupt controller #1
	outb %al,$0x20                  ! 第 190~191 行：回执 8259A
	movl CS(%esp),%eax
	andl $3,%eax		! %eax is CPL (0 or 3, 0=supervisor)
	pushl %eax                      ! 第 192~194 行：取被打断者的特权级
	call _do_timer		! 'do_timer(long CPL)' does everything from
	addl $4,%esp		! task switching to accounting ...
	jmp ret_from_sys_call           ! 第 197 行：走系统调用同款返程
```

两个细节：先给 8259A 发 EOI（回执）再干活，下一个 10ms 的脉冲就不会丢；
取被打断代码的 cs 低 2 位当参数传下去——**0 表示刚才在内核态，3 表示在
用户态**。真正的账房先生是 `kernel/sched.c` 第 305~336 行的 `do_timer`，
这次不省略，原文完整贴出：

```c
void do_timer(long cpl)
{
	extern int beepcount;
	extern void sysbeepstop(void);

	if (beepcount)
		if (!--beepcount)
			sysbeepstop();

	if (cpl)
		current->utime++;
	else
		current->stime++;

	if (next_timer) {
		next_timer->jiffies--;
		while (next_timer && next_timer->jiffies <= 0) {
			void (*fn)(void);
			
			fn = next_timer->fn;
			next_timer->fn = NULL;
			next_timer = next_timer->next;
			(fn)();
		}
	}
	if (current_DOR & 0xf0)
		do_floppy_timer();
	if ((--current->counter)>0) return;
	current->counter=0;
	if (!cpl) return;
	schedule();
}
```

逐行过一遍（行号按 sched.c）：第 307~312 行的 `beepcount` 是蜂鸣器还剩
几拍，每拍减一、减到 0 就停——内核连"哔"一声响多久都拿节拍当秒表；第
314~317 行按 `cpl` 记账，用户态记 `utime`、内核态记 `stime`；第 319~329
行巡视"闹钟串" `next_timer`（`add_timer()` 挂的软件定时器链表，第 272
行），每拍给队头减一、到期的摘下来执行回调；第 330~331 行照看软驱马达
超时。第 332~335 行是重心：`(--current->counter)>0` 把时间片**先减一再
比较**，还剩得多就返回；减到 0 先清成 0，再判断 `cpl`——在内核态就先不
打扰，等它返回用户态；在用户态，就 `schedule()`：**换人！**

`alarm()` 也要交代一句：它并不在 `do_timer` 里到期，只是把到期时刻记进
`current->alarm`（`sys_alarm`，第 344 行）；真正的检查在 `schedule()`
开头（第 109~116 行）——谁的 `alarm` 小于当前 `jiffies`，就置上 SIGALRM
信号位并清掉 `alarm`，随后沿 5.3.6 节的信号返程送达。回到主线：`jiffies`
（第 189 行每拍 `incl`）与 `counter` 就是第 6 章的燃料：**每 10ms，
counter 减一；减到 0 且在用户态，就 `schedule()` 换人**。

## 5.6 硬件中断的完整闭环：按下键盘之后

第 1 章 1.5 节的"主线剧情"第一幕——你敲下回车——现在可以看源码了。
标签级走一遍（不必逐行），全程约 100 行代码：

```
 按键按下
    │ 键盘控制器(8042)把按键编码成 1 字节"扫描码"
    ▼
 8259A 中断控制器：这是 1 号 IRQ → 向 CPU 发中断号 0x21
    │（IDT 第 0x21 项是谁登记的？console.c 第 683 行：
    ▼   set_trap_gate(0x21,&keyboard_interrupt);）
 kernel/chr_drv/keyboard.S 第 37 行  _keyboard_interrupt:
    │ 第 48 行  inb $0x60,%al     ← 从端口 0x60 读出扫描码
    │ 第 53 行  call key_table(,%eax,4)
    │            ← 又一张函数指针表！按扫描码分派：
    │               字母键 → do_self，换挡键 → lshift ……
    │ do_self 把扫描码翻译成字符，排进终端的输入队列
    ▼
 第 66~69 行：给 8259A 发 EOI，call _do_tty_interrupt
    ▼
 kernel/chr_drv/tty_io.c 第 343~345 行 do_tty_interrupt()
    → 第 145 行 copy_to_cooked()：加工字符（比如回车变换行）
    → 第 227 行 wake_up(&tty->secondary.proc_list)
```

最后一行 `wake_up` 是点睛之笔：shell 早就在等键盘输入——第 4 章说过它睡在
`TASK_INTERRUPTIBLE` 状态。**"睡眠"的进程不占 CPU，靠的就是"有事发生时
中断处理函数来叫醒它"**。shell 被唤醒，重新调度上 CPU，调用 `read()` 系统
调用——又回到 5.3 节那条通道，把字符取走。

一个完整的闭环：**按键（硬件）→ 中断（被动进门）→ 驱动收码 → 唤醒睡眠的
进程 → 进程用系统调用（主动进门）取走数据**。中断与系统调用，一扇被动门、
一扇主动门，合起来才构成"应用程序与外界沟通"的完整通路。

### 实验 5-2：绕过 printf，直接敲内核的窗口

```c
/* syscall_demo.c —— 不经过任何库函数包装，直接发起系统调用 */
#include <stdio.h>
#include <unistd.h>
#include <sys/syscall.h>    /* SYS_write、SYS_getpid 等编号在这 */

int main(void)
{
    char msg[] = "hello, kernel\n";

    printf("SYS_write 的编号 = %d\n", SYS_write);

    /* 直接发起 write 系统调用：fd=1 是标准输出。
     * 返回值和错误都由 syscall() 原样带回，没有 errno 包装 */
    long n = syscall(SYS_write, 1, msg, sizeof(msg) - 1);
    printf("write 返回 %ld（写入的字节数）\n", n);

    /* 一个不需要参数的系统调用：查本进程的进程号 */
    long pid = syscall(SYS_getpid);
    printf("getpid 返回 %ld（对照 getpid() 应相同）\n", pid);
    printf("再用库函数核对 getpid() = %d\n", (int)getpid());
    return 0;
}
```

```bash
gcc syscall_demo.c -o syscall_demo   # macOS 用 clang 也一样
./syscall_demo
```

**macOS/Linux 差异**：`syscall()` 和 `SYS_*` 宏两边都有，程序可直接编译；
但**系统调用号两边不同**（Linux 是自己的一套，macOS 是 BSD 风格的另一套），
所以第一行打印的编号两边会不一样——这本身就说明"调用号是内核的私房约定"。
在 Linux x86-64 上 `SYS_write` 恰好等于 1，跟 `fd=1` 撞了个满怀，纯属巧合；
macOS 上是 4，倒是和 0.11 的 `__NR_write = 4` 不谋而合。另外两点留意：

- macOS 会给 `syscall` 打"已弃用"的编译警告——苹果希望你走库函数和 Mach
  接口，本实验**照常能跑**，警告放着不管即可（这也算亲眼见证了"绕过窗口
  直接敲门"在现代有多受限制）；
- `syscall(SYS_write, ...)` 绕过了 stdio 的缓冲，输出顺序可能和 printf
  混搭——想想 5.8 节的误区一。

## 5.8 常见误区

**误区一："printf 是系统调用"。** 不对。printf 是用户态库函数，负责格式化
（纯计算，不需要特权）；真正进内核的是它最终调用的 write。这也解释了一个
现象：`printf` 少量输出时并不立刻出现在屏幕上——库先把字节攒在用户态缓冲
区，攒够一行或缓冲满才调一次 write。用 strace 数一数你的程序调了几次
write，就知道攒没攒。

**误区二：把中断号和系统调用号混为一谈。** `int 0x80` 的 0x80 是**中断号**
（查 IDT 用，决定从哪个门进内核）；`__NR_write = 4` 是**系统调用号**（查
sys_call_table 用，决定内核里哪个函数接活）。两次查表、两张表、两个号。
72 种系统调用共用 0x80 一扇门；反过来，0x80 这扇门也只管系统调用——键盘
走 0x21，时钟走 0x20。

**误区三：以为用户态/内核态是"两个程序"。** 态是 **CPU 的权限模式**，不是
程序的身份。执行 `write(1,...)` 前后是**同一个进程**：先以 Ring 3 跑你的
main()，`int 0x80` 后同一个进程的 CPU 换成 Ring 0 去跑 sys_write，iret
后又变回 Ring 3。变的只是工牌，不是人。

**误区四：以为系统调用会"随时打断"你。** 会被随时打断的是中断（异步，
来路不明）；系统调用是**同步**的——你的程序主动执行 `int` 指令，内核接单、
办完、返回，你的下一行代码才会继续。把"中断"和"系统调用"都想成打断，
是初学者最容易犯的归类错误。

## 5.9 对照现代：从 int 0x80 到 syscall 指令

0.11 的这套机制今天仍是骨架，但零件升级了：

- **进门指令**：x86-64 Linux 改用专用的 `syscall`/`sysret` 指令对替代
  `int 0x80`/`iret`——入口地址存在 CPU 的 MSR 寄存器里，不再查 IDT，开销
  更小；参数寄存器也换成 rdi/rsi/rdx/r10/r8/r9，调用号在 rax。int 0x80
  至今仍被保留支持，但已是"历史通道"。
- **调用号数量**：0.11 有 72 个系统调用（`nr_system_calls = 72`）；现代
  Linux x86-64 有 400 多个，多出来的大半是内存、文件、网络的现代化扩展
  （mmap、openat、epoll……第 11 章的 epoll 就是其中之一）。
- **连门都懒得进了**：gettimeofday 这类"只读时间"的调用走了 **vDSO**——
  内核把一小段代码映射进每个进程的地址空间，用户态直接执行就能算出时间，
  系统调用的开销全省。相当于物业把常用的办事窗口直接搬到了你家楼下。
- **各家用各的门**：macOS 的内核是另一套（BSD 风格系统调用号，实验 5-2
  里你亲眼见过编号不同）。所以"系统调用号"从来不是通用标准，而是每个
  内核自己的私房菜单。

## 5.10 门与特权级：为什么你能 int 0x80，却不能自己触发时钟中断

先看一组反差实验：`int 0x80` 每天被用户程序敲千万次，安然无恙；可要你在
程序里写一句 `int $0x20`（模拟时钟中断），0.11 里这个进程立刻被 CPU 拦下
——13 号异常（一般保护错误）落进 `general_protection` 门，进程当场被
`do_exit` 干掉。同样是 `int` 指令，凭什么待遇天差地别？答案在门描述符的
一个字段里：第 2 章 2.5 节讲过 Ring 0~3，而 IDT 的每项门描述符（8 字节）
里留了 2 位 **DPL（描述符特权级）**，含义是**这扇门最低从哪个特权级可以
敲**。填门的三个宏定义在 `include/asm/system.h` 第 22~40 行（原文）：

```c
#define _set_gate(gate_addr,type,dpl,addr) \
__asm__ ("movw %%dx,%%ax\n\t" \
	"movw %0,%%dx\n\t" \
	"movl %%eax,%1\n\t" \
	"movl %%edx,%2" \
	: \
	: "i" ((short) (0x8000+(dpl<<13)+(type<<8))), \
	"o" (*((char *) (gate_addr))), \
	"o" (*(4+(char *) (gate_addr))), \
	"d" ((char *) (addr)),"a" (0x00080000))

#define set_intr_gate(n,addr) \
	_set_gate(&idt[n],14,0,addr)

#define set_trap_gate(n,addr) \
	_set_gate(&idt[n],15,0,addr)

#define set_system_gate(n,addr) \
	_set_gate(&idt[n],15,3,addr)
```

三个包装宏只差两个参数：门类型（14=中断门、15=陷阱门）与 **DPL**——
前两个宏传 0，唯独 `set_system_gate` 传 **3**。属性值
`0x8000+(dpl<<13)+(type<<8)` 印证布局：0x8000 是"存在"位（bit 15），DPL
占第 13~14 位。CPU 的检查规则一句话：Ring 3 执行 `int N` 时，**CPL 必须
不大于门的 DPL（数值上）才放行**。`int 0x80` 的门由
`set_system_gate(0x80,&system_call)`（sched.c 第 411 行，5.2.2 节见过）
登记，DPL=3，放行——这扇"服务窗口"专门对用户开放；时钟（0x20 的
`set_intr_gate`）、键盘（0x21，5.6 节的 `set_trap_gate`）、除零（0 号）
等门 DPL=0，用户态 `int` 模拟一律被拦成保护异常——医院大门对所有人开放，
手术室门只认医生工卡。而 DPL 拦的是**软件 int 指令**，不是硬件事件：
除零并不是你执行 `int 0` 触发的，是 CPU 出错时自己查表进入，拦不住。

各扇门用什么宏登记，`kernel/traps.c` 第 183~191 行的 `trap_init` 开头（原文）：

```c
	int i;

	set_trap_gate(0,&divide_error);
	set_trap_gate(1,&debug);
	set_trap_gate(2,&nmi);
	set_system_gate(3,&int3);	/* int3-5 can be called from all */
	set_system_gate(4,&overflow);
	set_system_gate(5,&bounds);
```

第 6~47 号清一色 `set_trap_gate`（含 13 号 general_protection、14 号
page_fault）。对用户开放的只有 5 扇：0x80 和 3、4、5 号——第 188 行注释
"int3-5 can be called from all"，int3/into/bound 故意 DPL=3，调试器下
断点靠的正是用户程序自己执行 int3。最后留个钩子：`_set_gate` 那段
`movw %%dx,%%ax / movw %0,%%dx / ...` 是在寄存器里手工拼装 8 字节门
描述符再分两次写入 `idt[n]`——现在读不懂很正常，它正是附录 B 招式 6
（volatile 与内嵌汇编）的例题，读完附录回来再看，就当做一道练习。

## 5.11 内核的可重入：两个进程同时调用 write 会怎样

想象：进程 A 的 `sys_write` 执行到一半，时钟中断响了，`schedule()` 把 CPU
切给 B，B 也调用 `write`——内核里那份 `sys_write` 代码只有一份，两个
"工单"同时在办，会不会互相写串？不会，靠三件套：**代码一份，栈每人
一份**——进 `int 0x80` 时 CPU 自动切到该进程自己的内核栈（fork 时备好，
记在 task_struct 的 tss 里），各自的局部变量各在各的栈上；**`current`
指针标记"替谁办事"**——5.3.4 节清单里的 `movl _current,%eax`（第 96、
102 行）取的就是它，全局唯一，永远指向当前正在服务的进程，调度器
`switch_to` 换人时顺手更新；**数据按进程区分**——`write` 的 fd 是"该
进程的文件描述符表"的下标（第 9 章），A 的 1 号和 B 的 1 号是两条记录。

这就是**内核的可重入**：同一段内核代码办到一半被切走，再以另一进程的身份
重新进入，互不干扰。但可重入≠高枕无忧：若改的是**全局**数据（比如同一
终端的输出缓冲队列），A 写一半被打断、B 接着写同一份，字节就会交错——
0.11 靠进关键区先 `cli()`、出来再 `sti()` 护身，现代内核有自旋锁、信号量
一整套。所以内核里处处要小心竞态——第 12 章的伏笔埋在这里；且 0.11 是
单 CPU，"同时"实为交错，多核上两个核真的同时跑进 `sys_write`，才是第
12 章要正面迎战的战场。

## 本章小结

1. 屏幕点亮要碰硬件、特权指令只有内核能执行，一切硬件服务必须过"系统调用"窗口。
2. CPU 看 cs 低 2 位（CPL）区分内核态（0）/用户态（3）；态是 CPU 的属性，`int 0x80` 前后是同一进程在换工牌。
3. 中断号查 IDT 选门、系统调用号查 `sys_call_table` 选函数——两张表两个号，72 种系统调用共用一扇门。
4. `_syscall3` 宏：调用号进 eax、参数进 ebx/ecx/edx、`int $0x80`、返回值从 eax 接回；"失败 -1 + errno"是内核定的。
5. `system_call` 入口三件事：`cmpl`+`ja` 拿 72 拒收越界号；按 cdecl 从右到左压 edx/ecx/ebx；fs 换 0x17 留小窗。
6. 返程三岔口：`state`/`counter` 不合格调 `schedule()`；有未屏蔽的待处理信号送 `do_signal`；否则 `iret` 回用户态。
7. 门描述符 DPL 决定谁能敲门：0x80、int3 等 DPL=3 对用户开放；除零、时钟、键盘等 DPL=0，越权 `int` 被拦成保护异常。
8. 时钟 100Hz：`jiffies` 每拍加一、`counter` 每拍减一，减到 0 且在用户态就调 `schedule()`；内核靠栈+`current` 可重入但要防竞态（第 12 章）。
