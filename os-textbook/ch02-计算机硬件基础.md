> 4. 说清实模式与保护模式的区别——这是进入第 3 章的入场券；
> 5. 理解中断的工作流程，分清硬件中断与软件中断（`int` 指令）。

## 2.1 从一个问题开始：刚开机的电脑，为什么"假装"自己是 1981 年的老古董？

你的电脑是 64 位、内存几个 GB、能同时跑几十个程序。但每次按下电源键的最初几秒，
它却表现得像一台 1981 年的 IBM PC：16 位的脑子，只认得 **1MB** 内存，一次只能干一件事。

这不是故障，是刻意保留的"传统仪式"。CPU 每次开机都从一种叫**实模式**（real mode）的
古老状态醒来，随后由一小段代码（第 3 章的主角）把它"唤醒"成强大的**保护模式**
（protected mode）。

要读懂这段唤醒仪式——也就是读懂 `linux-0.11/boot/` 里那几百行汇编——你需要先认识
CPU 脚下的土地：寄存器、内存地址、栈、两种模式、中断。本章就讲这五样东西。
它们是纯硬件知识，不依赖任何操作系统；但操作系统的一切魔法都建立在这块土地上。

> **本章约定**：1991 年的 linux-0.11 跑在 32 位的 Intel 80386 上，所以源码里到处是
> `eax`、`esp` 这样的 32 位名字；而你的电脑是 64 位的，实验时看到的会是 `rax`、`rsp`。
> 别慌——64 位名字只是 32 位名字的"加长版"，看到 `r` 开头就自动脑补成 `e` 开头即可。

## 2.2 CPU：厨师手边的调料碟

先来个比喻。把 CPU 想象成一位厨师：

- **内存是货架**——空间大，什么原料都有，但从货架取东西要走几步路，比较慢；
- **寄存器是手边的调料碟**——只有那么七八个小碟，但伸手就能拿到，极快。

厨师炒一道菜，会把当下要用的盐、糖、酱油先舀进调料碟，而不是每放一撮盐都跑一趟
货架。CPU 同理：**算术必须在内部分量极少的寄存器里进行**，内存里的数据要先搬进
寄存器才能参与运算，算完再搬回内存。

**精确地说**：寄存器（register）是 CPU 内部的高速存储单元，数量只有十几个，
访问速度比内存快几十倍，而且——这点很重要——**寄存器没有地址**。内存每个字节
都有门牌号，寄存器没有，它们靠名字访问（`ax` 就是 `ax`，没有"第几号"的说法）。

内核时代的主角们的名字（左边 16 位时代，右边 32 位时代）：

```
  8086（16 位，实模式）        80386（32 位，保护模式）
  ─────────────────────       ─────────────────────
  ax bx cx dx     通用寄存器   eax ebx ecx edx
  cs ds ss es     段寄存器     cs ds ss es fs gs
  ip              指令指针     eip
  sp bp           栈指针/框架  esp ebp
  flags           标志位       eflags
```

记忆窍门，几个字母背后的含义：

| 名字 | 全称/含义 | 它是干什么的 |
|---|---|---|
| `ax` → `eax` | accumulator 累加器 | 干算术活的主力，函数返回值也放这里 |
| `cx` → `ecx` | count 计数器 | 当循环次数用 |
| `dx`、`bx` | data、base | 打杂：放数据、放地址 |
| `cs`、`ds`、`ss` | 代码段、数据段、栈段 | 程序分成三摊：指令一摊、数据一摊、栈一摊，各用各的段 |
| `ip` → `eip` | instruction pointer | 永远指向**下一条**要执行的指令——CPU 的"读到哪了"书签 |
| `sp` → `esp` | stack pointer | 永远指向**栈顶**——2.4 节的主角 |
| `bp` → `ebp` | base pointer | 指向当前函数的栈框架底部——函数的"锚" |

一个 32 位寄存器并不是凭空变大 16 位的，而是"套娃"：`ax` 是 `eax` 的低 16 位，
`ah`/`al` 又是 `ax` 的高/低 8 位。

```
31            16 15      8 7        0
┌───────────────┬─────────┬──────────┐
│   （高 16 位） │   ah    │    al    │
│               ├─────────┴──────────┤
│               │         ax         │
├───────────────┴────────────────────┤
│                eax                 │
└────────────────────────────────────┘
```

所以你在 0.11 的汇编里会同时看到 `mov ax,#...` 和 `movl $...,%eax`——不是写乱了，
是程序员按需挑碟子：搬 16 位数据用小碟，搬 32 位用大碟。

> **别被两种汇编语法吓到**：`mov ax, #0x9000`（Intel 风格，`setup.s` 用）和
> `movl $0x10, %eax`（AT&T 风格，`head.s` 用）说的是同一件事——"把数装进寄存器"。
> 本章你只需要认识指令的**意图**，不需要会写汇编。

## 2.3 内存与地址：带编号的格子

第二个比喻。把内存想象成一条极长的街，街上每 1 米一户格子间：

- 每个格子间住 **1 个字节**；
- 每个格子间有唯一的**门牌号**——这个门牌号就是**地址（address）**；
- "把 42 写到 0x2000 号"就是"往 0x2000 格子间塞一张写着 42 的纸条"。

**精确地说**：内存按字节编址，第 i 个字节的地址就是整数 i。32 位计算机的地址是
32 位二进制数，能表示 2^32 = 4GB 个格子；64 位机的地址有 64 位（常用 48 位）。

**指针，就是存门牌号的变量**：

```c
int x = 42;          // 在某个格子间住下，内容是 42
int *p = &x;         // p 是另一个格子间，内容是"x 的门牌号"
```

```
        变量 p（本身也占内存，64 位机占 8 字节）
        ┌──────────────────┐
        │      0x2000      │ ← p 的"值"是一个门牌号
        └──────────────────┘
                 │ 指向
                 ▼
地址        内容
  ...
0x2000      42        ← x 住在这里
  ...
```

`*p` 读作"顺着门牌号找过去"，所以 `*p` 就是 42；`p = &y` 是"把 p 里的门牌号换成 y 的"。
指针的一切魔法，本质都是**对门牌号的存和取**。

**大端小端，一句话**：一个 4 字节的 `int` 要占 4 个相邻格子，先放哪头？
**小端（little-endian）：低位字节放低地址**——x86 就是小端，可记成"数的低位住在
小门牌"；大端（big-endian）反之。`0x12345678` 在小端机器的内存里是
`78 56 34 12`（从低地址往高地址看）。本章知道这一句就够，第 9 章读文件格式时会再见。

## 2.4 栈：函数调用的后台账本

C 语言里写 `add(2, 3)`，函数怎么知道参数是 2 和 3？执行完又怎么知道该回到哪一行？
答案是一块特殊约定的内存区域——**栈（stack）**。

比喻：一摞盘子，只能放顶、拿顶（后进先出）。每调用一个函数，就往这摞盘子上
**叠一个新盘子**（该函数的"工作台"）；函数返回，就把顶上的盘子端走。

**精确地说**：栈是一段内存，向**低地址方向**生长（记住这点，2.8 节实验要验证它）。
`esp` 永远指向栈顶。两个专用指令维护它：`push`（压栈：`esp` 减 4，数据写入 `esp`
指的位置）、`pop`（出栈：读出并 `esp` 加 4）。

函数调用时，`call` 指令自动做两件事：**把返回地址压栈**（"回哪行"的便条），
然后跳到函数开头。函数结尾的 `ret` 把便条弹出来，跳回去。用这段代码画图：

```c
int add(int a, int b) {
    return a + b;
}
int main(void) {
    int r = add(2, 3);
    return 0;
}
```

`main` 执行到 `add(2, 3)` 时的栈（32 位示意）：

```
高地址
┌─────────────────────────┐
│  main 的局部变量 r       │
├─────────────────────────┤ ← main 的 ebp（main 的锚）
│  ...                    │
├─────────────────────────┤
│  返回地址（回 main）      │ ← call add 压入：执行完回哪
├─────────────────────────┤
│  a = 2                  │ ← 参数，从右往左压
│  b = 3                  │
├─────────────────────────┤
│  保存的 main 的 ebp      │ ← add 开头把自己的锚存好
│  （add 的局部空间）      │ ← esp：栈顶
└─────────────────────────┘
低地址        栈向下生长 ↑
```

`ebp` 的价值现在清楚了：`esp` 随着压栈出栈不停上蹿下跳，而 `ebp` 像一枚**锚**钉在
当前函数框架的底部。想取参数 `a`？从 `ebp` 往上数固定几格；想找局部变量？往下数。
"某函数的 `ebp` + 偏移"这个寻址方式，在 0.11 的汇编里反复出现。

每次"叠盘子"，都发生一次**栈帧（stack frame）**的建立：压参数、压返回地址、
保存并重设 `ebp`。函数一层层调用，栈帧一层层叠上去——这就是"调用栈"（call stack）。
如果递归没有出口，盘子会叠到天花板……然后砸穿地板（2.9 节的"栈溢出"）。

> **顺带揭晓一个第一章的悬念**：C 函数的"返回值"在硬件层面就是"把结果放进 `eax`"。
> 2.8 节实验 (b) 里你会亲眼看它发生。

## 2.5 两种模式：从"小区门全开"到"门禁卡"（重点）

现在回答 2.1 节的问题。CPU 有两种工作模式，差别之大，像两个世界：

| | 实模式 real mode | 保护模式 protected mode |
|---|---|---|
| 时代 | 8086（1981 PC 起） | 80386（1985）起 |
| 位数 | 16 位 | 32 位 |
| 能访问的内存 | 1MB（2^20） | 4GB（2^32） |
| 物理地址算法 | 段 × 16 + 偏移 | 查描述符表换算 |
| 段寄存器里存的 | 段基址本身 | 选择子（selector） |
| 保护机制 | **没有** | 越界、越权直接被硬件拦下 |

**比喻**：实模式是**小区大门全开**——任何住户（程序）可以走进任何一栋楼
（内存任何位置），能拆别人家具、能改物业记录，毫无约束；保护模式是**门禁卡 +
物业登记**——每栋楼登记在册（描述符表），刷卡进入（选择子），刷卡时保安核验
"你有没有权限、有没有越界"，越界立即报警（硬件异常）。

**实模式的精确规则**：8086 寄存器是 16 位的，最多数到 65535；但它的地址线有 20 根，
想摸到 1MB 内存。怎么办？把两个 16 位数拼起来：段寄存器 × 16（二进制左移 4 位）+
偏移，凑出 20 位地址：

```
  cs = 0x1000        ip = 0x0200
        │                  │
        ▼ ×16（16 进制下就是尾部添个 0）
 物理地址 = 0x10000    +   0x0200   =  0x10200
```

这个"段：偏移"是 16 位程序时代的万能钥匙。它简单，但**危险**：段基址就是光秃秃的
地址，没有任何检查——程序 A 可以算出程序 B 的地盘，想写就写。BIOS 就是活在
这个世界里的 16 位程序。

**保护模式的精确规则**：段寄存器的 16 位不再直接是地址，而是**选择子**——一张
"楼宇登记表"的行号。登记表有两张：全系统共用的 **GDT**（全局描述符表）和每个任务
自带的 **LDT**（局部描述符表）。表里每一行是一个**描述符**，记录着：这段内存从哪开始
（基址）、有多长（界限）、谁能用（权限）。

```
  cs = 0x0008（选择子）
        │ 低 13 位 = 行号 1，去登记表里查第 1 行
        ▼
      ┌─────┐ 行 1  ┌───────────────────────────┐
      │ GDT │ ────► │ 描述符：基址 + 界限 + 权限 │
      │     │ 行 2  │ （只读/可写？内核/用户？） │
      └─────┘  ...  └───────────────────────────┘
                            │
                            ▼
              得到这段内存的起点、长度、规则，
              CPU 硬件自动检查每次访问是否越界越权
```

（选择子 16 位里，低 2 位是请求特权级，中间 1 位选查 GDT 还是 LDT，其余 13 位是
行号——细节第 7 章还会见面，现在记住"选择子=登记表行号"即可。）

开机时 CPU 处于实模式，是为了**兼容**：让 1981 年的 DOS 程序在 386 上也能跑。
代价就是每个现代操作系统启动时都要先"委屈"在实模式里，做完几件只有 BIOS 能帮忙
的事，然后尽快切换到保护模式。**切换开关，就是第 3 章的故事**——不过你现在已经有
足够的词汇量预读剧情了：打开 A20 地址线（实模式的 20 根地址线之外还有一根被主板
掐断着的第 21 根，不打开就永远看不见 1MB 以上的内存），再设置 CR0 寄存器的 PE 位
（Protection Enable，保护使能）。

### 2.5.1 特权级：门禁卡的四个等级

"门禁卡"的比喻还差一半：卡有等级，门有门槛。x86 把特权级分成 0~3 四个环
（ring）：**内核住在 Ring 0**，什么都能干；普通应用程序住在 **Ring 3**，
一批"危险"指令（如 `lgdt`、`lidt`、`lmsw`）一碰就被硬件拦下（Ring 1、2 基本闲置）。

两个新词：**CPL**（当前特权级）是此刻工牌上的等级，**DPL**（描述符特权
级）是目标大门的门槛——**CPL 够不着 DPL，硬件当场拦下**。应用程序想用
内核的地盘不能翻墙，只能走"访客通道"——2.6 节的 `int` 指令；能否进门取决
于门描述符的 DPL：0.11 的系统调用门（0x80 号）把 DPL 开到最低，欢迎所有
程序来访，大多数门 DPL=0，按了也白按（细节第 5 章展开）。最后把"选择子
= 登记表行号"补完整，16 位选择子是这样拼的：

```
 15              3   2    1  0
┌──────────────────┬────┬──────┐
│    索引（13 位）  │ TI │ RPL  │
└──────────────────┴────┴──────┘
  去登记表查第几行    0=GDT 请求特权级
                     1=LDT （2 位）
```

拿 2.7 节反复出现的选择子 **8** 拆一拆：`0b0000000000001000`——索引 = 1
（查第 1 行）、TI = 0（查 GDT）、RPL = 0。所以 `jmpi 0,8` 意为"以 0 级
工牌，跳到 GDT 第 1 行代码段的偏移 0 处"——内核本来就在最高级，一路绿灯。

## 2.6 中断：硬件喊人的机制

想象你在写作业（CPU 在跑你的程序），这时**门铃响了**。你不会扔下笔傻站着——你会：

1. **记住进度**：在草稿上写下"写到第 3 题第 2 行"；
2. **去开门**：处理门外的事（收快递？问路？）；
3. **回来继续**：翻到草稿，从第 3 题第 2 行接着写。

CPU 处理**中断（interrupt）**就是这个流程的硬件版：

```
1. 门铃响      硬件（时钟/键盘/硬盘）向 CPU 发出一个中断号——"号码牌"
2. 记住进度    CPU 把 eip（断点）和标志寄存器压栈
3. 查号码牌    拿着号码牌去一张"表"里查：该找谁来处理
4. 开门        执行那个处理程序（interrupt handler，中断处理程序）
5. 回来继续    处理程序执行 iret，CPU 从断点处接着跑
```

步骤 3 里那张表，实模式和保护模式各有版本：

- **实模式：中断向量表（IVT）**。固定放在物理地址 0 处，256 项，每项 4 字节，
  存的是处理程序的"段：偏移"。N 号中断的信息就在 `0 + N×4` 处。
- **保护模式：中断描述符表（IDT）**。位置不固定，由 `lidt` 指令登记，256 项，
  每项 8 字节的"门描述符"，存处理程序入口和权限要求。

```
实模式 IVT（内存开头 1024 字节）
物理地址          内容
0x00000  ┌────────────────────────┐
         │ 0 号：处理程序段:偏移   │ 4 字节
0x00004  │ 1 号：处理程序段:偏移   │
         │ ...                    │
0x003FC  │ 255 号：处理程序段:偏移 │
         └────────────────────────┘
```

**号码牌有两来路**：

- **硬件中断**：外部设备喊人——时钟每秒响上百次（第 6 章调度的节拍器）、键盘每次
  按键都响（你敲下回车的那段旅程，第 1 章的 1.5 节，第一步就是它）。
- **软件中断**：程序**主动**执行 `int N` 指令喊人。这是应用程序进内核的正门——
  0.11 的系统调用就是 `int 0x80`（第 5 章主角）。

另外还有一类"假中断"——**异常（exception）**：程序自己出了事，除零、访问非法地址
（缺页）时 CPU 自动产生中断号，转给内核处理。它走的流程与中断一模一样。
广义上教材说"中断"时，常把硬件中断、软件中断、异常都算在内。

### 2.6.1 8259A 中断控制器：15 个设备的总机接线员

门铃很多，通到 CPU 的铃线只有几根，中间站着专用芯片 **8259A** 当"总机接线
员"：十几个设备把请求递给它，它挑一个优先级最高的转发给 CPU，并附上"号码
牌"（中断号）。这台总机是**两片级联**：主片管 IRQ0~7，占端口 0x20/0x21；
从片管 IRQ8~15，占端口 0xA0/0xA1，输出接到主片的 IRQ2 上——合计 15 路可用。

上岗前要按固定顺序往端口写 4 个**初始化命令字** ICW1~ICW4，最要紧的是
ICW2：**这组 IRQ 从几号开始编号**。麻烦恰恰出在这里——CPU 把中断号 0~31
留给**异常**（0 号除零、3 号断点、8 号双重故障……），BIOS 却按 1981 年的
老规矩把主片 IRQ0~7 编成 **0x08~0x0F**：时钟一响就是 8 号，正好撞上
"双重故障"。所以 linux-0.11 一进 setup.s 就重编程 8259A：主片改到 0x20
起、从片改到 0x28 起（合计 0x20~0x2F）——
具体字节 2.7 节逐行讲。两个日常操作：**屏蔽**（OCW1：往 0x21/0xA1 写掩码，
哪位是 1 哪路门铃暂时静音）和**应答 EOI**（OCW2：处理完一个中断要往 0x20
端口回一句"知道了"，否则接线员压着这单不撒手——2.7 节摘录里
`out #0x20,al` 写的就是这个端口，只是值不同）。

> **一句话总结**：中断让"一个 CPU"看起来能同时照顾几十件事——本质是干几行就被
> 门铃打断，去别处转一圈，再回来接着干。没有中断，键盘永远得不到响应。

## 2.7 源码导读：进保护模式的临门两脚

纸上谈兵结束。打开 `linux-0.11/boot/` 目录，里面三个文件就是开机后最早运行的代码
（第 3 章细讲装载过程，本章只看 `setup.s` 和 `head.s`，它们恰好把本章五个概念全用上了）。
汇编不要求逐行看懂。下面摘出几段最有看头的原文（逐字符照抄，注释也是
Linus 的原话），你只要找到标签、认出寄存器、跟上故事线即可。

**`linux-0.11/boot/setup.s`**——实模式的最后一班岗（16 位）。从标签 `start:` 开始：

1. **读硬件参数**：开头一串 `int 0x10`（光标、显卡）、`int 0x15`（取扩展内存大小）、
   `int 0x13`（硬盘信息），把结果存到 0x90000 附近——趁 BIOS 还管用，赶紧把家底
   打听清楚存进小本本；
2. **`cli` 关中断**：标签 `do_move:` 前一行。从这行起不再信任 BIOS 的中断服务，
   干脆把门铃线拔了（第 3 章讲为什么要先拔再接）；
3. **装载描述符表**：标签 `end_move:` 里的 `lidt idt_48` 和 `lgdt gdt_48`——把
   IDT、GDT 的位置登记给 CPU。文件末尾 `gdt:` 处能看到两张描述符的内容：
   一张代码段、一张数据段，各管 8MB；
4. **打开 A20**：往键盘控制器端口写命令，把被主板掐断的第 21 根地址线接上
   （2.5 节说过它）。完整的一幕（`boot/setup.s` 第 138~144 行）：

   ```asm
   	call	empty_8042
   	mov	al,#0xD1		! command write
   	out	#0x64,al
   	call	empty_8042
   	mov	al,#0xDF		! A20 on
   	out	#0x60,al
   	call	empty_8042
   ```

   两个数就是跟 8042 对的暗号：0xD1 是"我要写你的输出端口"，0xDF 把输出
   端口的第 1 位置 1——那一位在主板上连的正是 A20 门控。为什么地址线归
   键盘控制器管？说来话长：8086 只有 20 根地址线，"段×16+偏移"算出的略超
   1MB 的地址会**回卷**到内存开头，有的程序就靠回卷凑合活着；1982 年的
   80286 有 24 根地址线，回卷消失，老程序全乱了，IBM 便给第 21 根线加了
   个默认掐断的开关，引脚恰好空在 8042 上——"对暗号开 A20"就此成为保留节目（`call empty_8042` 是在等它的输入缓冲清空）。

5. **重编程中断控制器**：就是 2.6.1 节那位 8259A。BIOS 把时钟中断安在
   8 号，而保护模式里 8 号是 CPU 的"双重故障"异常——撞车了，必须把
   15 路硬件中断整体搬到 0x20~0x2F（`boot/setup.s` 第 154~174 行）：

   ```asm
   	mov	al,#0x11		! initialization sequence
   	out	#0x20,al		! send it to 8259A-1
   	.word	0x00eb,0x00eb		! jmp $+2, jmp $+2
   	out	#0xA0,al		! and to 8259A-2
   	.word	0x00eb,0x00eb
   	mov	al,#0x20		! start of hardware int's (0x20)
   	out	#0x21,al
   	.word	0x00eb,0x00eb
   	mov	al,#0x28		! start of hardware int's 2 (0x28)
   	out	#0xA1,al
   	.word	0x00eb,0x00eb
   	mov	al,#0x04		! 8259-1 is master
   	out	#0x21,al
   	.word	0x00eb,0x00eb
   	mov	al,#0x02		! 8259-2 is slave
   	out	#0xA1,al
   	.word	0x00eb,0x00eb
   	mov	al,#0x01		! 8086 mode for both
   	out	#0x21,al
   	.word	0x00eb,0x00eb
   	out	#0xA1,al
   ```

   对照 2.6.1 节逐组看：`0x11` 是 ICW1，宣布"开始初始化"，同时发给主片
   （0x20）和从片（0xA0）；`0x20`、`0x28` 写进主、从片的数据端口，是最关键
   的 ICW2——号码牌从 0x20/0x28 起编；`0x04`、`0x02` 是 ICW3，登记主从
   接线（从片挂在主片 IRQ2 上）；`0x01` 是 ICW4，选定 8086 模式。摘录
   末尾满地的 `.word 0x00eb,0x00eb` 是"跳到下一条指令"的空转指令，给反应
   迟钝的 8259A 留点时间；摘录之后还有一笔：写 0xFF 屏蔽全部中断。

6. **临门一脚**：最后两行——

   ```asm
   	mov	ax,#0x0001	! protected mode (PE) bit
   	lmsw	ax		! This is it!
   	jmpi	0,8		! jmp offset 0 of segment 8 (cs)
   ```

   `lmsw` 把 CR0 的 PE 位置 1——**从此 CPU 进入保护模式**。`jmpi 0,8` 用选择子 8
   （GDT 第 1 行，就是上面那张代码段描述符）跳往偏移 0——那是 `head.s` 的地盘。

**`linux-0.11/boot/head.s`**——保护模式的第一批住户（32 位，AT&T 语法）。从
`startup_32:` 开始：

1. 重新给 `ds`、`es`、`fs`、`gs` 装上数据段选择子 0x10，再用
   `lss _stack_start,%esp` 把 `esp` 指到内核自己的栈——**栈，2.4 节的主角，
   第一个安家**；
2. `call setup_idt`：给 256 个号码牌各配一张占位门卡（`boot/head.s` 第 78~93 行，AT&T 语法）：

   ```asm
   setup_idt:
   	lea ignore_int,%edx
   	movl $0x00080000,%eax
   	movw %dx,%ax		/* selector = 0x0008 = cs */
   	movw $0x8E00,%dx	/* interrupt gate - dpl=0, present */

   	lea _idt,%edi
   	mov $256,%ecx
   rp_sidt:
   	movl %eax,(%edi)
   	movl %edx,4(%edi)
   	addl $8,%edi
   	dec %ecx
   	jne rp_sidt
   	lidt idt_descr
   	ret
   ```

   前四行在攒一张门描述符：`edx` 先装上 `ignore_int` 的地址；`eax` 先放好
   选择子 0x0008（2.5.1 节拆过），再把 `edx` 低 16 位挪进 `ax`——`eax`
   恰好是"偏移低 16 位（高半）+ 选择子（低半）"；随后 `edx` 低 16 位换上
   0x8E00——门卡的"规格栏"：中断门、DPL=0（只许 0 级的自己人用）、存在
   位=1。循环体把两个寄存器各写 4 字节（`(%edi)` 收 `eax`、`4(%edi)` 收
   `edx`）拼出 8 字节表项；`ecx` 从 256 递减，256 张门卡全部指向只会打印
   "Unknown interrupt" 的 `ignore_int`——内核此时谁也不信任，门铃一响先喊"谁啊？"；

3. `call setup_gdt`：换上内核自己的 GDT（`_gdt:` 处，空表项 + 代码段、数据
   段两张有效描述符）。函数本体只有 `lgdt gdt_descr` 加 `ret` 两行——Linus
   自嘲"本函数复杂得整整有两行，值得配上这么长的注释"，而且干完活它就会
   被页表覆盖，连尸首都不留。真正的内容在 `_gdt:` 处，挑内核代码段描述符
   `0x00c09a0000000fff`（注释标着 16Mb），按 2.3 节的小端规则拆成 8 字节：

   ```
   字节    0    1  │ 2    3    4  │  5  │   6   │ 7
   内容   FF   0F │ 00   00   00 │ 9A  │  C0   │ 00
         └─界限低16位─┘ └─基址低24位─┘  │   └─ 界限高4位=0；G=1（以4KB计）、D=1
                                        └─ 访问权 0x9A：存在、DPL=0、代码段、可读
   字节 7 = 基址最高 8 位（00）→ 基址 = 0x00000000；界限 0x0FFF、G=1 → 段长 16MB
   ```

   看出别扭之处了吗？**32 位段基址被拆成三截**，散在字节 2~4 和字节 7 里
   ——不是笔误，是历史包袱：表项格式在 80286 时代（24 位基址）就定了型，
   386 想塞进 32 位基址又不肯推翻旧格式，只好把最高 8 位藏进最后一个字节。
   读描述符**永远按位段拆着读，别当一个大整数读**。setup.s 那张临时 GDT
   格式完全相同，只是界限填 0x07FF——2048×4096 = 8MB（源码注释原话）；

4. `after_page_tables:`：往栈里压 0、0、0 和 `_main`——**这是给 C 语言写的
   `main()` 函数准备的参数和返回地址**（2.4 节的调用约定，汇编亲自示范了一遍），
   然后 `jmp setup_paging`；
5. `setup_paging:`：建立页目录和 4 张页表（`pg0`~`pg3`，映射 16MB 内存，`boot/head.s` 第 198~218 行）：

   ```asm
   setup_paging:
   	movl $1024*5,%ecx		/* 5 pages - pg_dir+4 page tables */
   	xorl %eax,%eax
   	xorl %edi,%edi			/* pg_dir is at 0x000 */
   	cld;rep;stosl
   	movl $pg0+7,_pg_dir		/* set present bit/user r/w */
   	movl $pg1+7,_pg_dir+4		/*  --------- " " --------- */
   	movl $pg2+7,_pg_dir+8		/*  --------- " " --------- */
   	movl $pg3+7,_pg_dir+12		/*  --------- " " --------- */
   	movl $pg3+4092,%edi
   	movl $0xfff007,%eax		/*  16Mb - 4096 + 7 (r/w user,p) */
   	std
   1:	stosl			/* fill pages backwards - more efficient :-) */
   	subl $0x1000,%eax
   	jge 1b
   	xorl %eax,%eax		/* pg_dir is at 0x0000 */
   	movl %eax,%cr3		/* cr3 - page directory start */
   	movl %cr0,%eax
   	orl $0x80000000,%eax
   	movl %eax,%cr0		/* set paging (PG) bit */
   	ret			/* this also flushes prefetch-queue */
   ```

   开头 4 行把 5 页清零（页目录 + 4 张页表）；随后往页目录前 4 格写
   `pg0+7`~`pg3+7`，`+7` 顺手置上"存在、用户可读写"属性位；接着从最高
   表项 `0xfff007` 起**倒着**填表（`std` 后 `stosl` 一路减地址），把
   0~16MB 的每个 4KB 页一一登记。最后三行：页目录地址装进 CR3，CR0 或上
   0x80000000 置 PG 位——**分页开启**。分页是什么？第 7 章的绝对主角，
   这里只需知道它是"保护模式plus"的内存管理手段。

读完这两脚，回头看 2.1 节：**谁把 1981 年的老古董唤醒成现代电脑？**就是
`setup.s` 里的 `lmsw ax`。一百多行汇编，穿越了 1981→1985 年的四年硬件进化。

> **读码小惊喜**：`setup.s` 里有 `lds si,[4*0x41]` 这样的行——BIOS 把硬盘参数表的
> 地址存在 IVT 的第 0x41 号"中断向量"格子里，setup.s 直接按 `4×0x41` 算出格子位置，
> 把它**当数据**偷了出来。看，IVT 不但能"查处理程序"，还是块现成的储物格。

## 2.8 动手实验

三个实验，macOS 和 Linux 都能跑（需要 gcc 或 clang）。

### 实验 (a)：地址与指针大小——亲眼看见"格子编号"

保存为 `addr_demo.c`：

```c
#include <stdio.h>

int global_var = 100;               /* 全局变量：住"数据区" */

int main(void) {
    int   local_var = 42;           /* 局部变量：住"栈" */
    int  *p = &local_var;           /* 指针：存 local_var 的门牌号 */

    printf("sizeof(char)   = %zu\n", sizeof(char));
    printf("sizeof(int)    = %zu\n", sizeof(int));
    printf("sizeof(int *)  = %zu   <-- 指针大小\n", sizeof(int *));

    printf("&global_var = %p\n", (void *)&global_var);
    printf("&local_var  = %p\n", (void *)&local_var);
    printf("p           = %p   (和 &local_var 相同吗?)\n", (void *)p);
    printf("*p          = %d\n", *p);
    return 0;
}
```

编译运行：

```bash
gcc -g -O0 -o addr_demo addr_demo.c && ./addr_demo
```

一份 64 位机器上的输出（**地址每次运行、每台机器都不同**，这是正常且故意的）：

```text
sizeof(int *)  = 8        <-- 64 位机：指针 8 字节；32 位机会是 4
&global_var = 0x104000030
&local_var  = 0x16d76315c
p           = 0x16d76315c (和 &local_var 相同吗?)
*p          = 42
```

三个观察点：**①** 指针大小等于"一个门牌号要多长"——64 位机 8 字节、32 位机 4 字节；
**②** `&global_var` 和 `&local_var` 相差十万八千里：一个在数据区、一个在栈上；
**③** `p` 的**值**打出来就是 `&local_var`——指针就是格子编号，2.3 节的图活了。
（顺带看看 `&local_var` 是不是比 `&global_var` "更大"或"更小"，不同系统方向不同，
这正说明栈和堆是两块地盘，2.9 节揭晓。）

### 实验 (b)：用调试器看寄存器——亲眼看 `eax` 接住返回值

保存为 `reg_demo.c`：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int r = add(2, 3);
    printf("r = %d\n", r);
    return 0;
}
```

```bash
gcc -g -O0 -o reg_demo reg_demo.c   # -O0 关闭优化，寄存器用法更"教科书"
```

**Linux（gdb）**：

```bash
gdb ./reg_demo
(gdb) break main          # 在 main 处停下
(gdb) run
(gdb) info registers      # 一口气看全部寄存器
(gdb) step                # 走进 add 函数
(gdb) finish              # 把 add 执行完，停在返回处
(gdb) info registers eax  # 看看谁装着返回值 5
(gdb) quit
```

**macOS（lldb，Xcode 自带）**：

```bash
lldb ./reg_demo
(lldb) breakpoint set --name main
(lldb) run
(lldb) register read
(lldb) s                  # step，走进 add
(lldb) finish
(lldb) register read rax  # 64 位版的 eax
(lldb) quit
```

你会看到一大排 `rax`、`rbx`、`rip`、`rsp`……对，就是你电脑的 64 位寄存器（`e` 系的
加长版）。重点观察：`finish` 之后 **`rax`（32 位视角即 `eax`）里是 5**——
"函数返回值"这个 C 概念，在硬件层面就是"把结果放进 `eax`"。再对照 `rip`/`eip`
（下一条指令在哪）和 `rsp`/`esp`（栈顶在哪），2.2 节的表格全部对上号。

### 实验 (c)：观察栈的生长方向——递归往下走吗？

保存为 `stack_demo.c`：

```c
#include <stdio.h>

void dive(int depth) {
    int local = depth;                              /* 每层递归自己的局部变量 */
    printf("depth=%3d  &local=%p\n", depth, (void *)&local);
    if (depth < 4)
        dive(depth + 1);                            /* 往更深处跳 */
}

int main(void) {
    dive(0);
    return 0;
}
```

```bash
gcc -g -O0 -o stack_demo stack_demo.c && ./stack_demo
```

典型输出（节选）：

```text
depth=  0  &local=0x16d763148
depth=  1  &local=0x16d763118
depth=  2  &local=0x16d7630e8
depth=  3  &local=0x16d7630b8
depth=  4  &local=0x16d763088
```

地址**一次比一次小**——每次递归调用叠一个新栈帧，栈顶 `esp` 一路**向低地址**推进，
2.4 节说的"栈向下生长"实锤了。相邻两层的差值（这里是固定的 48 字节）就是一个
栈帧的实际大小：局部变量 + 保存的 `ebp` + 对齐填充，各编译器略有不同。

> **注意**：一定要用 `-O0`。开优化后编译器可能把递归"展平"或复用变量，地址就不
> 规矩了——那也是很有意思的观察，但先看规矩的版本。

## 2.9 常见误区

**误区一：把 `eax` 当变量用。**
"我能写 `&eax` 或者给 `eax` 赋值吗？"——不能。寄存器**没有地址**（2.2 节），
C 语言里根本不存在 `eax` 这个标识符，它是 CPU 的私有财产。想用寄存器？
只能把数据读进变量（编译器自会安排），或者在汇编里用名字访问。

**误区二：把地址当普通整数随便算。**
地址确实是整数（格子编号），但随便算它会出事：`p + 1` 加的不是 1，而是
`sizeof(*p)` 个字节（指针运算按类型步进）；两个不相关的指针相减、比较没有意义；
把随手编的数字强转成指针再解引用（`*(int *)0x1234`），轻则读到垃圾，重则段错误。
地址可以做有限的算术（同一数组内），但要清楚自己踩在哪块地盘上。

**误区三：以为栈在"堆"里。**
"栈""堆"是内存里**两块方向相反的地盘**：栈由函数调用自动管理、向下生长、
函数返回即回收；堆由 `malloc`/`free` 手动管理、向上生长、不还就漏。实验 (a) 里
`&global_var` 与 `&local_var` 天各一方，实验 (c) 里地址一路变小——它们住在不同街区。
"栈溢出"（递归太深）砸的是栈的地盘，和堆没有关系。

## 练习题

**2.1（概念）** 用"厨师与调料碟"的比喻，向室友解释：为什么 CPU 不直接在内存里
完成所有计算？（提示：从货架上取一撮盐要几步？从调料碟呢？这个差距在硬件上
是几十倍的访问速度。）

**2.2（计算）** 实模式下 `cs = 0x2000`、`ip = 0x01F0`，物理地址是多少？
再算一遍 `cs = 0x1234`、`ip = 0x5678`。（提示：段 × 16 在十六进制下就是尾部
添一个 0，再做加法。答案是 0x201F0 和 0x179B8。）

**2.3（操作）** 把实验 (c) 的 `if (depth < 4)` 改成 `if (depth >= 0)`（永远递归），
重新编译运行，观察它是怎么"死"的；再执行 `ulimit -s`（macOS 和 Linux 都支持）
查一下你的栈上限是多少 KB。
（提示：死法叫"段错误"（Segmentation fault），因为栈长到了没人给它留的地盘上。
macOS 主线程栈默认 8MB，Linux 常见默认也是 8MB。）

**2.4（思考）** `setup.s` 在切换保护模式前先执行 `cli` 关中断。假设不关，
切换的一瞬间正好时钟中断响了，会发生什么？（提示：门铃响了，但号码牌查询表
刚从 IVT 换成 IDT，旧表已经作废——CPU 会拿着 8 号去查一张还没填好的新表，
调用一个错误的"处理程序"。）

**2.5（预习）** 打开 `linux-0.11/boot/head.s`，找到 `setup_idt`，看它的循环
（标签 `rp_sidt`）把多少个表项填成 `ignore_int` 的地址？每个表项几个字节？
（提示：`mov $256,%ecx` 是循环次数，`addl $8,%edi` 是每次前进的字节数——
256 个号码牌 × 每牌 8 字节，正是 2.6 节说的保护模式 IDT 规格。）

## 本章小结

- 寄存器是 CPU 手边的"调料碟"：极快、没有地址、靠名字访问；内存每字节有唯一门牌号，指针就是存门牌号的变量；x86 是小端（低位字节住小门牌）。
- 栈向低地址生长：`call` 压返回地址，`esp` 指栈顶，`ebp` 是函数框架的锚；返回值放 `eax` 是硬件层约定。
- 实模式：段×16+偏移拼 20 位地址、摸到 1MB、无保护；保护模式：段寄存器装选择子，查 GDT/LDT 换算地址，越界越权硬件拦下。
- 描述符 8 字节里 32 位基址分散在三处——按位段拆着读，别当一个大整数。
- 选择子 16 位 = 13 位索引 + TI 位 + 2 位 RPL；选择子 8 = GDT 第 1 行、0 级请求。
- 特权级 Ring 0~3：CPL 是工牌等级、DPL 是门禁门槛，不够就被拦；进内核要走 DPL 允许的 `int` 门。
- 中断 = 门铃：硬件发号码牌，CPU 压断点、查 IVT（实模式）或 IDT（保护模式），`iret` 回来接着跑。
- 8259A 两片级联管 15 路 IRQ；BIOS 编号 0x08~0x0F 与异常 0~31 冲突，故重编程到 0x20~0x2F，处理完发 EOI。
- A20 是 8086 地址回卷的兼容遗物，第 21 根地址线由键盘控制器 8042 把守，进保护模式前对暗号打开。
- `lmsw ax` 置 CR0 的 PE 位、`jmpi 0,8` 跳进内核代码段——唤醒 1981 年老古董的就是这两行。
