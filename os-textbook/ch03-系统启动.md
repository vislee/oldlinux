## 3.1 从一个问题开始：没有程序，怎么运行程序？

你每天按下电源键，几秒后屏幕亮起、桌面出现——好像理所当然。但请想一想这个
**鸡生蛋问题**：内存（RAM）一断电就"失忆"，开机瞬间里面**一个程序都没有**；
而程序必须被装进内存才能运行——"把程序装进内存"这个动作本身，也需要一个
程序来执行。

谁来打破死循环？答案是主板上焊着的一小块**不会失忆的芯片**（ROM）：出厂时
就烧好了一段叫 **BIOS** 的程序，CPU 一通电就去执行它，由它把操作系统从硬盘
（1991 年是软盘）里"请"进内存。

但 BIOS 只认识 512 字节的小扇区，而内核有十几万字节。于是启动注定不是一个人的
战斗，而是一场**接力赛**：BIOS 跑第 0 棒，0.11 内核的三个文件
（`boot/bootsect.s`、`boot/setup.s`、`boot/head.s`）跑第 1、2、3 棒，
最后把接力棒递给 C 语言写的 `main()`——物业经理正式上岗，第一个进程诞生。
本章就沿这条时间线跑完全程：**每个小节就是一棒，每棒都有明确的任务和交接动作**。

## 3.2 核心概念：自举，与一场四棒接力

### 3.2.1 复位：CPU 醒来的第一眼

CPU 的硬件设计保证：**复位（加电或按 reset）之后，它永远从物理地址 0xFFFF0
取第一条指令**。这是写死在芯片里的行为（第 2 章讲过，实模式下物理地址 =
段寄存器 × 16 + 偏移；复位时 CS:IP 恰好指向 0xFFFF0）。

0xFFFF0 是实模式 1MB 空间的最顶端再往下 16 字节。IBM PC 的设计者把这块区域
留给了一片 ROM——BIOS 就住在那里。CPU 醒来执行的第一条指令通常是一个
远跳转，跳进 BIOS 程序的主体。

BIOS 接下来做三件事：

1. **POST（加电自检）**：清点内存、检查键盘、显卡、硬盘是否健在；
2. **找启动盘**：按设定的顺序（软盘 → 硬盘 →……）读每个盘的**第一个扇区**；
3. **交棒**：把该扇区（512 字节）搬到 **0x7C00**，检查末两字节是不是
   签名 `0xAA55`，是则跳到 0x7C00 开始执行——从此 BIOS 再也不管事了。

> **一个 1981 年的历史包袱**：为什么偏偏是 0x7C00？当年的 IBM PC 最低只配
> 32KB 内存。BIOS 设计者决定把引导扇区放在内存顶端附近：留 512 字节给引导
> 扇区、再留 512 字节给自己做数据区，于是引导扇区落在 32KB − 1KB = 0x7C00。
> 这个"随手一放"成了 x86 四十年的规矩，今天的 UEFI 之前时代仍然遵守它。

### 3.2.2 引导扇区：512 字节的入场券

**定义**：引导扇区（boot sector）是启动盘的第一个扇区，共 512 字节，
其最后两个字节（第 510、511 字节）必须是 `0x55 0xAA`（即 16 位小端数
`0xAA55`）。BIOS 只凭这两字节判断"这是一个可引导的扇区"。

注意"小端"：源码里写作 `.word 0xAA55`，但落到磁盘上是先存低字节 `55`、
再存高字节 `AA`（x86 是小端序，第 2 章讲过）。你可以翻到 3.3 节的
`bootsect.s` 最后几行亲眼看这个签名。

512 字节装不下任何操作系统，它唯一的使命是**把更大的内核加载进内存**。
这个"程序自己加载自己"的过程叫**自举（bootstrap）**——词源是《吹牛大王
历险记》里揪着自己的鞋带（bootstraps）把自己从泥潭里提起来的故事，
计算机术语 **boot（启动）** 就源于此。

### 3.2.3 实模式地址换算：段 × 16 + 偏移

启动前半程 CPU 工作在**实模式**（8086 兼容模式），程序给出的地址是
"段:偏移"两个 16 位数，物理地址 = 段寄存器值 × 16（左移 4 位）+ 偏移。
本章会反复用到几组换算，请先熟悉：

| 段:偏移写法 | 换算 | 物理地址 | 谁住在这里 |
|---|---|---|---|
| 0xF000:0xFFF0 | 0xF000×16 + 0xFFF0 | **0xFFFF0** | BIOS（ROM） |
| 0x07C0:0x0000 | 0x07C0×16 + 0 | **0x7C00** | 引导扇区被 BIOS 装到这里 |
| 0x9000:0x0000 | 0x9000×16 + 0 | **0x90000** | bootsect 搬家后的新家 |
| 0x9000:0x0200 | 0x9000×16 + 0x200 | **0x90200** | setup.s 被装到这里 |
| 0x1000:0x0000 | 0x1000×16 + 0 | **0x10000** | 内核主体先卸到这里 |

同一个物理地址可以有无数种"段:偏移"写法（例如 0x7C00 也等于
0x0000:0x7C00），读启动代码时永远用公式换算成物理地址再思考，才不会迷路。

### 3.2.4 四棒总览

| 棒次 | 代码（linux-0.11/ 下） | 关键地址 | 一句话职责 | 比喻 |
|---|---|---|---|---|
| 第 0 棒 | BIOS（主板 ROM，不在源码树里） | 0xFFFF0 → 跳 0x7C00 | 自检、装第一扇区 | 发令员 |
| 第 1 棒 | `boot/bootsect.s`（约 260 行汇编） | 0x7C00 → 0x90000 | 搬自己，装 setup 和内核 | 边跑边搬队友 |
| 第 2 棒 | `boot/setup.s`（约 230 行汇编） | 0x90200 执行 | 收参数、内核搬到 0、进保护模式 | 领队兼搬家公司 |
| 第 3 棒 | `boot/head.s`（约 240 行汇编） | 0x00000 执行 | 建正式 GDT/IDT、开分页 | 汇编最后一棒 |
| 终点 | `init/main.c` 的 `main()` | C 语言世界 | 总装初始化、fork 出第一个进程 | 物业经理上岗 |

一图胜千言（地址都是物理地址）：

```
电源 ─► BIOS ─► bootsect.s ──────► setup.s ──────► head.s ─► main() ─► init()
      0xFFFF0   0x7C00→0x90000      0x90200          0x00000     C 语言    1 号进程
      实模式    实模式，用 BIOS      实模式→保护模式   32 位保护    接管一切   PID=1
                int 13h 装盘        jmpi 0,8 换挡    模式+分页
```

下面逐棒细看。

## 3.3 源码导读 I：bootsect.s——边跑边搬队友的第一棒

打开 `linux-0.11/boot/bootsect.s`。它被 BIOS 装到 0x7C00 后从标签 `start`
（第 46 行）开始执行。**第一件事不是加载内核，而是搬家**（第 47~56 行）：

```asm
entry start
start:
	mov	ax,#BOOTSEG      ! ds = 0x07C0（自己现在住的地方）
	mov	ds,ax
	mov	ax,#INITSEG     ! es = 0x9000（新家）
	mov	es,ax
	mov	cx,#256          ! 拷 256 个字（word）= 512 字节
	sub	si,si
	sub	di,di
	rep
	movw                   ! 逐字搬运：0x7C00 → 0x90000
	jmpi	go,INITSEG      ! 远跳转到 0x9000 段——从此在新家执行
```

为什么要搬？内核最终的家在低地址（setup.s 马上要把整个内核搬到 0x00000
起），0x7C00 正落在那片地盘上——不搬走就会被自己请来的内核"坐"在身下。
bootsect 搬到高处的 0x90000，顺便把栈安在 0x9FF00（第 60~62 行）。

搬家完毕，开始搬队友。第 67~77 行用 BIOS 的磁盘服务 `int 0x13`（第 2 章
介绍过 BIOS 中断）把 setup 的 4 个扇区读进来：

```asm
load_setup:
	mov	dx,#0x0000		! drive 0, head 0
	mov	cx,#0x0002		! sector 2, track 0
	mov	bx,#0x0200		! 地址 = 0x90200（es 段内偏移 0x200）
	mov	ax,#0x0200+SETUPLEN	! 服务号 2（读盘），读 SETUPLEN=4 个扇区
	int	0x13			! 读！
	jnc	ok_load_setup		! 成功（无进位标志）就继续
	mov	dx,#0x0000
	mov	ax,#0x0000		! 失败则复位软盘
	int	0x13
	j	load_setup		! 重来
```

注意 `SETUPLEN = 4`（第 34 行）——setup.s 一共只占 4 个扇区（2KB），
落位在 0x90200，紧挨着 bootsect 的新家。

接下来 `ok_load_setup`（第 79 行）起是重头戏：先打探磁盘参数（每磁道
几个扇区），再用 `int 0x10` 在屏幕上打出那句著名的

```asm
msg1:
	.byte 13,10
	.ascii "Loading system ..."
```

（第 244~247 行。3.8 节实验 2 里你会在 QEMU 窗口亲眼看到它。）
然后调用 `read_it`（第 151 行）把**内核其余部分**——head.s 和全部 C 代码
链接成的 system 模块，大小由 `SYSSIZE` 限制在约 196KB——逐磁道读到
**0x10000** 处。`read_it` 里的 `rp_read` 循环（第 156 行）小心地不让每次
读盘跨越 64KB 边界（BIOS 软盘服务的老毛病）。读完还顺手 `kill_motor`
（第 233 行）关掉软驱电机，"让我们以一个干净的状态进入内核"。

最后一段收尾很有仪式感（第 249~253 行）：

```asm
.org 508
root_dev:
	.word ROOT_DEV         ! 根文件系统设备号（0x306，编译时写死）
boot_flag:
	.word 0xAA55           ! 引导签名——BIOS 就认这 2 个字节！
```

第 139 行的 `jmpi 0,SETUPSEG` 把控制流交给 0x90200 处的 setup.s。
第一棒跑完：**自己到了新家，setup 装好了，内核卸在 0x10000**。
所谓"边跑边搬自己的队友"，就是这个意思。

## 3.4 源码导读 II：setup.s——收情报、搬家、换挡

打开 `linux-0.11/boot/setup.s`。它从 0x90200 的 `start`（第 31 行）开始，
是四棒里**任务最杂**的一棒，干了五件事。

**第一件事：向 BIOS 打探硬件情报，抄在纸条上藏好。** 下一棒之后 BIOS 就
不能再用了（原因见本节末尾），必须趁现在把参数问出来。setup.s 依次调用
BIOS 中断，把结果统一存到 0x90000 起的一片区域（bootsect 老窝腾出的地方）：

| 参数 | BIOS 调用 | 存放地址 | setup.s 行号 |
|---|---|---|---|
| 光标位置 | `int 0x10`（AH=3） | 0x90000 | 38~41 |
| **扩展内存大小（KB）** | `int 0x15`（AH=0x88） | **0x90002** | 45~47 |
| 显卡模式/窗口 | `int 0x10`（AH=0x0F） | 0x90004、0x90006 | 51~54 |
| EGA/VGA 信息 | `int 0x10`（AH=0x12） | 0x90008~0x9000C | 58~63 |
| 硬盘 0/1 参数 | 取自 BIOS 数据区向量 0x41/0x46 | 0x90080、0x90090 | 65~87 |

记住 **0x90002 存的是扩展内存大小**——3.6 节 `main.c` 开头会直接
从这根"纸条"上读数，这是两棒之间传情报的暗号。

**第二件事：把内核整体搬到最终地址 0x00000。** 第 109 行先执行 `cli`
关中断（搬家时不能被打断），然后 `do_move` 循环（第 115~126 行）每次
搬运 64KB，把 0x10000 起的内核一卡车一卡车向下倒，直到整个模块落到
0 地址：

```asm
do_move:
	mov	es,ax		! 目地段，从 0x0000 起
	add	ax,#0x1000
	cmp	ax,#0x9000	! 源段到达 0x9000 就收工
	jz	end_move
	mov	ds,ax		! 源段（从 0x1000 起）
	sub	di,di
	sub	si,si
	mov 	cx,#0x8000	! 每次 0x8000 个字 = 64KB
	rep
	movsw
	jmp	do_move
```

> **为什么敢"鸠占鹊巢"？** 实模式下内存最低的 1KB（0x000~0x3FF）是 BIOS
> 的**中断向量表**——CPU 响应中断时查的"分机号表"（第 2 章）。现在中断
> 已被 `cli` 关闭、中断控制器马上要重新编程，这张表再也不需要了，于是
> 内核大大方方搬进这块黄金地段。循环在上边界 0x9000 处停下，也是为了
> 别踩坏存参数的 0x90000 保险箱。

**第三件事：装临时的"户口系统"。** `end_move`（第 130 行）执行
`lidt idt_48` 和 `lgdt gdt_48`，装入两个临时表（表就放在 setup.s 文件
末尾，第 205~224 行）：

- **GDT（全局描述符表）**：保护模式下"段"不再是数字，而是查表的"选择子"。
  这张临时 GDT 只填两项：8 号 = 基址 0、限长 8MB 的**代码段**；
  16 号 = 基址 0、限长 8MB 的**数据段**；
- **IDT（中断描述符表）**：暂时 limit=0，等于"空表"——反正中断已经关了。

**第四件事：打开 A20 地址线。** 8086 只有 20 根地址线，超过 1MB 的地址会
"绕回"到 0。从 286 起地址线变多了，但为了兼容老程序，IBM 在主板上加了个
叫 **A20 门**的开关：不开，第 21 根地址线被掐住，0x100000 仍会被当成 0。
搞笑的是，这个开关当年蹭在了**键盘控制器（8042）的一个空闲引脚**上——
所以 setup.s 第 138~144 行要给键盘控制器发命令（端口 0x64/0x60，写 0xD1
再写 0xDF）才能打开它；`empty_8042`（第 198 行）负责等控制器不忙。

**第五件事：换挡——进入保护模式。** 第 154~179 行先把中断控制器 8259
重新编程（BIOS 把硬件中断放在 0x08~0x0F，和 CPU 异常冲突，setup 把它们
改到 0x20~0x2F，第 5 章你会再遇到这组号）。然后是全书最关键的四行：

```asm
	mov	ax,#0x0001	! protected mode (PE) bit
	lmsw	ax		! This is it!
	jmpi	0,8		! jmp offset 0 of segment 8 (cs)
```

`lmsw` 置起 CR0 寄存器的 **PE 位**——CPU 从此进入**32 位保护模式**：
段寄存器变成查 GDT 的选择子，地址线全部打开，再没有 1MB 的紧箍咒。
`jmpi 0,8` 跳到"8 号选择子、偏移 0"——查刚才那张临时 GDT，8 号段基址
为 0，所以就是跳到**物理地址 0x00000**。那里现在住着谁？内核刚被搬到 0
地址，开头正是 head.s。第二棒交棒完成。

> **为什么进保护模式后就用不了 BIOS 了？** BIOS 的所有服务例程
> （`int 0x10`、`int 0x13`……）都是 16 位实模式代码，靠实模式中断向量表
> 寻址。保护模式下段寄存器含义变了、IDT 又是空表，贸然调用等于自杀。
> 这就是 setup.s 必须抢在 `lmsw` 之前把所有情报收齐、抄到 0x90000 的原因。

## 3.5 源码导读 III：head.s——汇编的最后一棒

打开 `linux-0.11/boot/head.s`。这是**第一段真正的 32 位代码**（AT&T 语法，
`movl $0x10,%eax` 即 `mov eax,0x10`），从物理地址 0 开始执行
（`_pg_dir:`、`startup_32:`，第 16~17 行）。文件开头有句重要注释
（第 10~12 行）：**启动代码就待在 0 地址，而这里以后要放页目录表**——
head.s 注定要被自己建的数据结构覆盖。它像脚手架：楼（页表）建好那天，
就是它被拆掉之时。head.s 干四件事。

**第一，重建正式的 GDT/IDT。** `setup_idt`（第 78 行）给 IDT 填 256 个
门，全部指向 `ignore_int`——一个打印 `"Unknown interrupt"` 的占位处理
程序（第 148~170 行）。真正的中断处理程序以后由 `main()` 里的
`trap_init()` 逐个替换（第 5 章）。`setup_gdt`（第 105 行）装入正式 GDT：
16MB 的代码段与数据段，取代 setup.s 的临时 8MB 版。

**第二，安顿栈、验证 A20、检查协处理器。** `lss _stack_start,%esp`
（第 23 行）把栈顶指到 `user_stack` 数组顶端（定义在
`linux-0.11/kernel/sched.c` 第 67~72 行，4KB）。第 32~36 行用了个聪明的
办法验证 A20 真的开了：往地址 0 写一个数，再读 0x100000 处——如果
两处相等，说明地址绕回了，A20 没开，原地死循环报警。

**第三，初始化页表，打开分页。** `setup_paging`（第 198~218 行）先清零
5 页内存：1 页**页目录** + 4 页**页表**；再填页目录的 4 个表项，分别指向
pg0~pg3 四张页表（`.org 0x1000` 预留，第 114~124 行），每张页表填 1024 项。
数学很简单：

```
每页 4KB × 每张页表 1024 项 × 4 张页表 = 16MB
```

也就是把**前 16MB 物理内存一比一映射**（虚拟地址 = 物理地址，叫恒等映射；
分页的完整原理第 7 章讲）。最后置 CR0 的 PG 位打开分页，`ret` 返回
（第 218 行注释：顺带清空了 CPU 的预取队列）。

**第四，交棒给 C。** 这是本章最精巧的三行戏法（第 135~141 行）：

```asm
after_page_tables:
	pushl $0		# These are the parameters to main :-)
	pushl $0
	pushl $0
	pushl $L6		# return address for main, if it decides to.
	pushl $_main
	jmp setup_paging
```

head.s 先把 main 的地址压栈（连同三个 0 当参数、一个死循环标号 L6 当
"返回地址"），然后跳去建页表。而 `setup_paging` 的最后一条指令是 `ret`——
返回到哪？栈顶正是 `_main`！**用一次"函数返回"，跳进了 C 语言的世界**。

> **至此汇编全部退场。** 三段汇编合计不到 800 行，干的都是同一类活：
> 搬运、填表、拨开关——C 语言写不动的部分，它们替你干完了。
> "汇编的最后一棒，交棒给 C"：从下一行起，全内核都是 C 了。

## 3.6 源码导读 IV：main.c——C 语言接手，第一个进程诞生

打开 `linux-0.11/init/main.c`，找到第 104 行：

```c
void main(void)		/* This really IS void, no error here. */
```

Linus 特意注释"这真是 void，不是写错了"——标准 C 的 main 应返回 int，
而内核的 main 被 head.s 用 `ret` 跳进来，永远不会"返回"。

### 3.6.1 十个 init 的总装流水线

`main()` 先从"纸条"上读 setup.s 留下的情报（第 58~60 行，直接把物理地址
当指针用），再按内存大小划定缓冲区边界，然后依次调用各子系统的初始化。
**调用顺序（第 126~135 行）如下**，每行标注它管什么、哪章细讲：

| 行号 | 调用 | 初始化什么 | 详见 |
|---|---|---|---|
| 126 | `mem_init()` | 主内存的占用记账表 | 第 7 章 |
| 127 | `trap_init()` | 把 IDT 的占位门换成真正的中断处理程序 | 第 5 章 |
| 128 | `blk_dev_init()` | 块设备（硬盘/软盘）请求队列 | 第 10 章 |
| 129 | `chr_dev_init()` | 字符设备 | 第 10 章 |
| 130 | `tty_init()` | 终端（键盘与屏幕） | 第 10 章 |
| 131 | `time_init()` | 从 CMOS 读出开机时刻 | — |
| 132 | `sched_init()` | 调度器：进程 0 号、时钟中断 | 第 4、6 章 |
| 133 | `buffer_init()` | 高速缓冲区（读写盘的缓存） | 第 9 章 |
| 134 | `hd_init()` | 硬盘中断挂接 | 第 10 章 |
| 135 | `floppy_init()` | 软盘中断挂接 | 第 10 章 |

紧接着（第 136~138 行）是本章的三个"历史性瞬间"：

```c
	sti();			/* 开中断——内核的心跳从此开始 */
	move_to_user_mode();	/* 从内核态切换到用户态 */
	if (!fork()) {		/* 我们赌它一定成功 */
		init();
	}
	for(;;) pause();
```

### 3.6.2 物业经理搬进员工工位：move_to_user_mode()

CPU 现在处于**内核态**（特权级 0，权限最大）。但操作系统是"物业"，物业
不能自己占着 CPU 干活，它要变成一个**可被调度的普通进程**（0 号任务），
把 CPU 让给真正的"业主"——用户程序。`move_to_user_mode()` 用一段内联
汇编伪造一次中断返回，把特权级从 0 降到 3；0 号任务从此和其他进程一样
排队等 CPU，只在没人可跑时兜底空转（"闲逛进程"）。切换细节第 5 章详述，
这里记住比喻：**物业经理办完入职手续后，自己也搬进了员工工位**。

随后的 `if (!fork())`（第 138 行）是**全内核第一个进程诞生**：`fork()`
复制出 1 号进程去执行 `init()`，父进程（0 号）则永远在
`for(;;) pause();` 里空转（第 148 行）。main 到此使命结束——它再也不能
调用任何函数，连 fork 都是内联汇编展开的：文件开头注释（第 11~22 行）
解释了原因（fork 后父子共用栈会出乱子，细节见第 4 章）。

### 3.6.3 第一个进程 init()：回答第 1 章练习 1.3

`init()`（第 168 行）是系统里**第一个正经干活的任务**，它做三件事：

```c
	setup((void *) &drive_info);            /* 通知内核硬盘参数 */
	(void) open("/dev/tty0",O_RDWR,0);      /* 打开 0 号终端 */
	(void) dup(0);                          /* 复制出 1 号描述符 */
	(void) dup(0);                          /* 复制出 2 号描述符 */
```

第一，打开终端设备 `/dev/tty0`，再 `dup` 两次，凑齐 **stdin（0）、
stdout（1）、stderr（2）** 三个标准描述符——此后所有进程的"标准输入
输出"都由此继承而来（文件描述符第 9 章细讲）。

第二，fork 出子进程打开 `/etc/rc` 并执行 shell 跑一遍初始化命令
（第 179~185 行，相当于今天的开机脚本）。

第三，进入死循环（第 189~207 行）：不停 fork 新进程执行
`execve("/bin/sh",...)`——**登录 shell**；shell 退出（你注销了）就打印
退出码，再 fork 下一个。这是"多用户系统"最朴素的雏形。

**现在可以揭晓第 1 章练习 1.3 了**：你在 `ps aux` 里看到的 PID 最小的
进程，通常正是 **init（现代 Linux 上多为 systemd），PID = 1**——它是
开机后 fork 出的**第一个进程**，此后所有进程都是它的子孙，编号按出生
顺序递增。而 PID 0（0 号任务）只在内核里兜底空转，永远不会出现在 ps 里。
从 1991 年到今天，这个传统没变过。

## 3.7 启动流程总图

把四棒接力连同内存变化画在一张图上（地址均为物理地址）：

```
按下电源
   │  CPU 复位，从 0xFFFF0 执行 BIOS（ROM）
   ▼
第 0 棒 BIOS：POST 自检 → 找启动盘 → 把第 1 扇区装到 0x7C00，
              检查末两字节 == 55 AA → 跳 0x7C00
   │  实模式，16 位
   ▼
第 1 棒 bootsect.s（0x7C00 执行）：
   ① 搬自己 0x7C00 → 0x90000，栈安在 0x9FF00
   ② int 13h：setup 4 扇区 → 0x90200
   ③ int 13h：内核主体（≤196KB）→ 0x10000
   ④ 打印 "Loading system ..."，关软驱电机 → jmpi 0,SETUPSEG
   │  仍是实模式，0x90200 执行
   ▼
第 2 棒 setup.s：
   ① 打探硬件参数 → 存 0x90000~0x901FC（含内存大小@0x90002）
   ② cli 关中断；内核整体上移 0x10000 → 0x00000（鸠占鹊巢）
   ③ 装临时 GDT/IDT；开 A20；8259 中断号改到 0x20~0x2F
   ④ lmsw 置 PE 位 → 保护模式；jmpi 0,8 → 跳物理地址 0
   │  32 位保护模式，0x00000 执行
   ▼
第 3 棒 head.s：
   ① 重建正式 GDT/IDT（256 门暂指 ignore_int）
   ② 栈顶 → user_stack；验证 A20；检查数学协处理器
   ③ 建页目录 + pg0~pg3（映射前 16MB），置 PG 位开分页
   ④ 压 _main 入栈，ret —— 交棒给 C
   │  init/main.c 第 104 行
   ▼
终点 main()：mem_init → trap_init → blk/chr_dev_init → tty_init
   → time_init → sched_init → buffer_init → hd/floppy_init
   → sti 开中断 → move_to_user_mode()（变 0 号任务）
   → fork() 出 1 号进程执行 init() → open tty0、dup×2
   → /etc/rc → execve /bin/sh —— shell 出现，启动完成！
```

配套的内存"搬家前后"对照（只画关键区域）：

```
 搬家前（setup.s 执行中）                搬家后（head.s / main 执行时）
 0x9FF00 ┬───────────────               0x9FF00 ┬───────────────
 0x90200 ├ setup.s                      0x90200 ├ setup.s（仍在）
 0x90000 ├ bootsect.s + 参数区          0x90000 ├ 硬件参数保险箱
 0x10000 ├ 内核主体（先卸这里）          0x05000 ├（head.s 的脚手架区）
 0x07C00 ├ bootsect.s 的老窝            0x00000 ├ 页目录 + 页表 + 内核
 0x00000 ┤ 中断向量表（将被覆盖）               │ （内核最终的家）
         ┴                                      ┴
```

## 3.8 动手实验

### 实验 1：亲手造一个引导扇区

BIOS 的验收标准只有一条：512 字节、末两字节 55 AA。我们自己造一个。
把下面的程序存为 `gen_boot.c`，它能生成一张"开机在屏幕上打一个 A"的
引导盘镜像：

```c
/* gen_boot.c —— 生成 512 字节引导扇区 boot.bin */
#include <stdio.h>

int main(void) {
    unsigned char buf[512] = {0};

    /* 几条 16 位实模式机器码（第 2 章学过 int 指令）： */
    buf[0] = 0xB4; buf[1] = 0x0E;   /* mov ah,0x0E  BIOS"电传打字"输出 */
    buf[2] = 0xB0; buf[3] = 0x41;   /* mov al,'A'   要打印的字符        */
    buf[4] = 0xCD; buf[5] = 0x10;   /* int 0x10     调用 BIOS 视频服务 */
    buf[6] = 0xEB; buf[7] = 0xFE;   /* jmp $        原地死循环          */

    buf[510] = 0x55;                /* 引导签名：.word 0xAA55 小端落盘为 55 AA */
    buf[511] = 0xAA;

    FILE *fp = fopen("boot.bin", "wb");
    fwrite(buf, 1, sizeof(buf), fp);
    fclose(fp);
    return 0;
}
```

编译、生成、观察：

```bash
gcc gen_boot.c -o gen_boot && ./gen_boot
od -Ad -tx1 boot.bin | head -2    # 看开头：b4 0e b0 41 cd 10 eb fe ...
od -Ad -tx1 boot.bin | tail -1    # 看结尾：…… 00 00 55 aa ← 签名在这！
ls -l boot.bin                    # 确认恰好 512 字节
```

再用模拟器验证它真的能"启动"（无需装系统）：

```bash
qemu-system-i386 -drive format=raw,file=boot.bin
```

弹出的窗口里出现一个白色的 **A**——恭喜，你写出了人生第一段自由运行的
裸机代码。把 `buf[3]`（'A' 的 ASCII 码 0x41）改成别的字符再试一次。

### 实验 2：在模拟器里启动 Linux 0.11

本仓库只有 0.11 的**源码**，没有编译好的镜像（也不要用现代编译器去编译
它们，见 README 的警告）。可启动的 `Image` 镜像有两个来源：

   的可启动镜像；
2. 按 `doc/Linux内核完全注释v5.0.pdf` 书末**附录**提供的 Bochs 配置文件
   与镜像制作步骤，用 Bochs 跑起来。

用 QEMU 的话（macOS 先 `brew install qemu`，Ubuntu
`sudo apt install qemu-system-x86`）：

```bash
# 把下载的镜像文件命名为 Image，放在当前目录
qemu-system-i386 -drive format=raw,file=Image
```

对照本章观察 QEMU 窗口：先看到 bootsect.s 打的 `Loading system ...`，

最后是 1991 年的 shell 提示符。**屏幕上的每一行字，你都能在本章找到是
哪一棒哪几行代码打出来的**——这就是读懂源码的乐趣。

### 实验 3：对比现代内核的启动日志

0.11 整个启动过程只打 3 行字。现代 Linux 内核启动要打几百行日志。在
Linux 终端（macOS 也可）执行：

```bash
dmesg | head -20     # 最早的 20 条内核日志：内存探测、CPU 特性、中断控制器……
dmesg | wc -l        # 数一数总共多少条，和 0.11 的 3 行对比
ps -p 1              # PID=1 的进程是谁？通常是 systemd 或 init
```

`dmesg` 的前几行是现代内核的"setup.s 时刻"（探测内存、CPU）；`ps -p 1`
里那个 PID=1 的进程，就是 `main.c` 第 138 行 fork 出的 init 的直系后代
——机制三十多年没变，只是体积大了三个数量级。

## 3.9 常见误区

1. **"内核是一个双击运行的程序。"**
   恰恰相反：启动那一刻，能"双击"的桌面还不存在。可执行文件格式
   （ELF）、加载器、shell 全是操作系统的产物，而它们此刻都还没被装进
   内存。所以启动代码必须是**不需要任何加载器的裸机器码**，并且自己
   把自己搬到该去的地方——这就是"自举"一词的含义。

2. **把"段:偏移"当拼接或普通加法。**
   `0x9000:0x0200` 不是 0x90000200，也不是 0x90202，而是
   0x9000×16 + 0x0200 = **0x90200**。请养成习惯：见到"段:偏移"先换算成
   物理地址再思考；同一物理地址有无数种写法（0x7C00 = 0x07C0:0x0000）。

3. **"启动 Linux 当然要靠 GRUB，GRUB 是 Linux 的一部分。"**
   GRUB 不是 Linux 的一部分，1991 年也根本不存在（诞生于 1995 年前后）。
   0.11 时代 BIOS 直接加载引导扇区，`bootsect.s` 自己就是"第一级加载器"。
   后来内核膨胀到远超一张软盘、又要支持多系统共存，才需要 GRUB 这样专职的
   引导程序站在 BIOS 和内核之间（现代机器换成 UEFI 后故事又翻新一页）。
   但铁律永远成立：第一段代码没有任何加载器可依赖。

4. **"main() 是内核执行的第一个函数。"**
   不是。main 之前，BIOS、bootsect.s、setup.s、head.s 已跑了几百行指令；
   main 甚至不是被"调用"的——是 head.s 把它的地址压栈后用 `ret`
   "骗"进去的。内核里处处是这类务实的小戏法，看到反常规的写法，
   先别急着当成 bug。

## 本章小结

- 加电后 CPU 从 **0xFFFF0** 执行 BIOS：自检 → 找启动盘 → 把第一个扇区装到
  **0x7C00**，凭末两字节签名 **0xAA55**（小端在盘上是 `55 AA`）决定是否交棒；
- 实模式地址 = 段 × 16 + 偏移；读启动代码永远先换算成物理地址再思考；
- 四棒接力：`bootsect.s`（0x7C00→0x90000，装 setup 到 0x90200、内核到 0x10000）
  → `setup.s`（收硬件参数存 0x90000 附近、把内核搬到 0x00000、开 A20、
  8259A 重编程到 0x20~0x2F、`lmsw` 置 PE 位进保护模式）
  → `head.s`（重建正式 GDT/IDT、建页目录与 4 张页表映射 16MB）
  → `main.c`；
- 进入保护模式后就**不能再调用 BIOS 中断**了——IDT 已换、CPU 模式已换，
  这就是 setup.s 必须"赶在搬家前收情报"的原因；
- `main.c`：按序调用 mem_init/trap_init/blk_dev_init/chr_dev_init/tty_init/
  time_init/sched_init/buffer_init/hd_init/floppy_init，`sti` 开中断，
  `move_to_user_mode()` 让内核进程态化，第一个 `fork()` 产出 **1 号进程**；
- 1 号进程打开 `/dev/tty0`、`dup` 两次造出 stdin/stdout/stderr，再执行 shell——
  你终端里的 PID=1 之祖；
- 今天的 UEFI/GRUB 代替了 BIOS 的角色，但"第一段代码自己加载自己"的自举思想
  四十年未变。
