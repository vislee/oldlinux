# 第 1 章 操作系统导论

> **学习目标**
> 1. 能用自己的话说出"操作系统是什么、它管什么"；
> 2. 知道 Linux 的诞生故事，理解本仓库里那一串版本号的含义；
> 3. 建立全教材的地图：每一章在学操作系统的哪个部件。

---

## 1.1 从一个问题开始：谁来给硬件"排班"？

想象一栋没有物业的大楼：

- 楼里只有一层是**真的能干活的地方**（CPU 只有一个），几百户人家（程序）都想用它；
- 每户家里堆满家具（数据），但楼的储藏室（内存）位置有限，怎么分配？
- 水电管道（键盘、硬盘、网卡）就那么几套，谁来接、怎么轮流用？

没有物业，每户只能自己协调——上一户用 CPU 忘了搬走，下一户就得等；两户同时往
储藏室同一格塞东西，互相覆盖。计算机在 1940~1950 年代就是这栋没有物业的大楼：
**一次只能跑一个程序，程序直接摸硬件，谁也别想同时运行**。

**操作系统（Operating System, OS）就是这栋大楼的物业**：

1. **资源管理者**：把 CPU 时间切成小片轮流分给各程序（第 6 章），把内存切块记账
   （第 7 章），把硬盘的读写排队（第 10 章）；
2. **服务提供者**：程序想读文件、想联网、想打印，不用自己驱动硬件，
   调用物业提供的**系统调用**（第 5 章）就行；
3. **秩序维护者**：不让 A 程序踩坏 B 程序的内存，不让任何程序独占 CPU（第 2、7 章）。

一个精确定义：**操作系统是管理计算机硬件资源、为应用程序提供服务的系统软件**，
它始终驻留在内存中，是开机后第一个真正"接管"机器的大型程序。

> **常见误区**：浏览器、Word 不是操作系统的一部分；但窗口系统（如 GNOME）
> 是否算 OS 的一部分要看口径——本教材采用狭义口径：**内核（kernel）+ 必要的基础设施**。
> 我们仓库里的 `linux-0.11/` 就是一个狭义的操作系统：只有内核，连图形界面都没有。

## 1.2 操作系统管哪四样东西

本教材的章节划分，其实就是"物业的四项核心业务"：

| 管什么 | 概念 | 章节 | 0.11 内核中的对应目录 |
|---|---|---|---|
| **CPU 时间** | 进程与调度 | 第 4、6 章 | `kernel/`（fork.c、sched.c） |
| **内存** | 虚拟内存与分页 | 第 7 章 | `mm/`（memory.c） |
| **数据存放** | 文件系统 | 第 9 章 | `fs/`（一大堆 .c） |
| **外部设备** | I/O 与驱动 | 第 10 章 | `kernel/blk_drv/`、`kernel/chr_drv/` |

加上贯穿所有业务的两个机制——**中断**（硬件喊人的方式，第 2、5 章）和
**系统调用**（程序找物业办事的窗口，第 5 章），操作系统的骨架就齐了。

第 11、12 章讲网络与并发：内核把 TCP/IP 协议栈建好之后，用户程序（以 nginx 为例）
怎么用 socket、epoll 这些"物业提供的窗口"写出能同时服务上万连接的程序。

## 1.3 Linux 诞生记：一个芬兰大学生的作业

1991 年，赫尔辛基大学 21 岁的本科生 **Linus Torvalds** 想给自己的 386 电脑写一个
能同时跑多个"终端任务"的小系统。他在邮件列表里发了那条著名消息：

> "我正在做一个（免费的）操作系统（只是个爱好，不会像 GNU 那样大而专业）……"

这条消息发自 **1991 年 8 月 25 日**。之后几个月的节奏，正好对应仓库里的目录：

- **`linux-0.00`**：1991 年中的雏形（只有启动、两个进程来回切换），目录里的
  `Image` 就是当年能启动的内核镜像；
- **1991-09-17**：`linux-0.01` 发布——第一个正式版本，约一万行 C 和汇编，
  还没有网络、没有软盘驱动，甚至注释稀少（日期由 Linus 本人事后考据确认）；
- **1991-10-05**：`0.02` 在 comp.os.minix 新闻组公开发布，这是 Linux 第一次
  "见网友"，10 月 5 日因此常被当作 Linux 的**公开生日**；
- **1991-12**：`linux-0.11` 发布，Linus 自述它"已具备 Unix 内核的大部分功能"；
- **1992 年初**：`0.12` 改用 GNU GPL 协议——这个"换牌照"决定了 Linux 后来的世界。

版本演进表（对应仓库目录，行数是约数）：

| 版本 | 时间 | 规模 | 里程碑 |
|---|---|---|---|
| 0.00 / 0.01 | 1991 | 1 万行 | 能启动、两个任务切换；只有 64 行注释的 fork |
| **0.11** | 1991.12 | 约 1.7 万行 | **第一个能自洽运行整套工具的版本**：多进程、分页内存、MINIX 文件系统、硬盘/键盘/串口驱动——本教材主力 |
| 0.12 | 1992.1 | 约 2 万行 | 引入数学协处理器模拟、更多修复 |
| 0.98 / 1.0 | 1992~1994 | 10 万+ 行 | 网络子系统并入、 成为正式 1.0 |
| 1.2.0 / 2.4.0 | 1995 / 2001 | 150 万 / 400 万行 | 多平台、SMP、USB…… |
| 2.6.0 / 2.6.12 / 2.6.35 | 2003~2010 | 600 万~1200 万行 | O(1) 调度 → **CFS 调度**（2.6.23 起，见 `linux-2.6.35/kernel/sched_fair.c`） |

为什么第 3~10 章用 **0.11** 讲？因为它有个黄金平衡点：

1. **小**：全内核不到 2 万行，一个大作业周就能通读；
2. **全**：进程、调度、分页、文件、驱动、系统调用一样不少，现代内核的每个子系统
   都能在这里找到"婴儿版"；
3. **有权威导读**：赵炯《Linux内核完全注释》（本仓库 `doc/` 目录里就有 PDF）
   对 0.11 做了逐行注释，与本章教材配套使用效果最佳；
4. **能跑**：配合模拟器（Bochs/QEMU）可以真机启动（第 3 章实验）。

而 **`nginx-0.1.0`**（2004 年发布，已在本仓库被逐行中文注释）是"用户态的另一半故事"：
内核把 TCP/IP、进程、内存管理做好之后，一个 Web 服务器是如何站在内核肩膀上工作的。
第 11、12 章你会打开它读真实代码——那里有 `accept()`、epoll、零拷贝和"惊群"问题。

## 1.4 操作系统在计算机系统中的位置

把一台计算机画成三层：

```
┌─────────────────────────────────────┐
│   应用程序层                          │  bash, gcc, nginx, 你的作业程序
├─────────────────────────────────────┤
│   操作系统内核                        │  进程/内存/文件/设备管理 ← 本教材
│   （linux-0.11/ 或 linux-2.6.35/）   │
├─────────────────────────────────────┤
│   硬件                               │  CPU、内存、硬盘、网卡 ← 第 2 章
└─────────────────────────────────────┘
        ↑ 应用只能通过"系统调用"这道门进入内核
```

关键规则：**应用程序不直接碰硬件，一切硬件操作都要托内核代办**。
你在 C 语言里写的 `printf("hello")`，一路会走到内核的写文件逻辑（第 9 章），
再走到终端驱动（第 10 章），最后由显卡把字符画上屏幕。
第 5 章你会亲眼看到这扇"门"在 0.11 里就是一条汇编指令 `int 0x80`。

## 1.5 全教材地图：一个回车键的旅程

本教材的"主线剧情"是追踪一次真实的计算机活动——**你敲下键盘上的回车，
shell 打印出一行字**——看看每一章的内容在其中扮演什么角色：

1. 回车按下 → 键盘产生**中断**（第 2 章）→ 键盘驱动收下扫描码（第 10 章）；
2. shell 正 blocked 在**读文件/读终端**上——它是一个**进程**（第 4 章），
   正在**睡眠等待**（第 6 章）；
3. 中断唤醒 shell → shell 调用 `read()` **系统调用**（第 5 章）拿到字符；
4. shell 通过**管道**或直接解析你的命令（第 8 章）；
5. 它 `fork()` 出子进程并 `exec()` 你的程序（第 4 章）→ 调度器给它 CPU（第 6 章）；
6. 你的程序从**文件系统**里被读出（第 9 章），按**页**装进内存（第 7 章）；
7. 程序输出又走一遍系统调用→驱动→屏幕（第 5、10 章）；
8. 如果你敲的是 `curl http://...`，那还要加上 TCP/IP 与 epoll（第 11 章）。

读完本教材，这条链路上每一环你都能打开源码指出"就是这几行代码干的"。

## 1.6 怎么学：读码三遍法

操作系统是"实践学科"，光看书期末必忘。推荐每章这样过：

1. **第一遍**：读本章概念部分，合上书自己复述比喻；
2. **第二遍**：打开"源码导读"指定的文件，找到那个函数，逐行读——读不懂的行记下来，
   对照《Linux内核完全注释》或问老师；
3. **第三遍**：做"动手实验"，**改代码**——改一行，预测结果，编译运行验证。
   预测错了的地方，就是你理解有洞的地方。

> **给初学者的一句话**：读不懂内核源码不是你的问题——1991 年的 C 代码风格
> 和今天不同，而且内核处处是指针花活。第 2 章会补齐汇编基础，
> 附录 B 专门整理了内核里最常见的 C 语言技巧（函数指针表、结构体嵌套、宏函数）。

## 练习题

**1.1（概念）** 用"物业"的比喻向你的室友解释：为什么两个程序不能各自直接操作硬盘？

**1.2（操作）** 在你的电脑上执行 `uname -r`，记录内核版本号；再对照 1.3 节的表格，
估计它比 linux-0.11 大多少倍。（提示：现代内核源码约 3000 万行。）

**1.3（观察）** 在终端执行：

```bash
ps aux | head -5
```

你看到的每一行都是一个"进程"（第 4 章主角）。找出其中 PID 最小的那个进程，
猜猜它为什么编号那么小（答案在第 3 章）。

**1.4（思考）** Linux 0.01 只有约一万行代码，却已经需要"进程切换"；
而现代手机 App 随便就几十万行。请猜测：0.01 的两个"任务"分别是什么？
（提示：见 `linux-0.00/` 目录和 `linux-0.01/init/main.c` 的最后几行。）

**1.5（预习）** 打开 `linux-0.11/kernel/fork.c`，数一数你认识的 C 语言构造
（if、for、结构体、指针……）和**不**认识的构造。把不认识的记下来，
第 2 章和附录 B 会解决它们。

## 本章小结

- 操作系统 = **资源管理者 + 服务提供者 + 秩序维护者**：管 CPU 时间、内存、
  数据存放、外部设备四样东西；
- 应用程序不直接碰硬件，一切硬件操作都要穿过**系统调用**这扇门进入内核；
- Linux 诞生于 1991 年：8 月 25 日 Linus 发帖宣布，9 月 17 日 0.01 问世，
  10 月 5 日 0.02 公开发布，12 月的 **0.11** 已"具备 Unix 内核的大部分功能"；
- 0.11 是初学者的黄金版本：**不到 2 万行**却五脏俱全，且有《Linux内核完全注释》
  （仓库 `doc/` 目录）逐行导读；
- 现代内核（2.6.35，仓库 `linux-2.6.35/`）是 0.11 的后代：调度器从 40 行长成
  几千行，但进程、分页、文件、驱动这些骨架一一对应；
- `nginx-0.1.0`（已逐行注释）是内核的"用户态客户"：第 11、12 章借它看真实
  服务器如何用 socket/epoll/锁；
- 本教材主线剧情是"一次回车键的旅程"：中断 → 进程 → 系统调用 → 管道 →
  fork/exec → 调度 → 文件 → 内存 → 驱动，每章补上一环；
- 学法：**读码三遍法**——读概念、读源码、改代码，预测错了的地方就是理解有洞的地方。
