# nginx 0.1.0 TCP/IP 源码逐行注释 —— Linux 操作系统理论对照说明

## 一、为什么选 nginx 0.1.0

nginx 由 Igor Sysoev 开发，**0.1.0 是 2004-10-04 发布的第一个公开正式版本**。
nginx 是运行在 Linux 用户态的 Web 服务器，它本身不实现 TCP/IP 协议栈，而是**通过 Linux 内核提供的
socket 系统调用接口（socket/bind/listen/accept/connect/send/recv/epoll...）完整地使用内核 TCP/IP 协议栈**。
因此 0.1.0 版本虽小（src 约 2 万行），却完整包含了基于 TCP/IP 协议的服务端编程全路径：

```
socket() → setsockopt(SO_REUSEADDR) → bind() → listen() → epoll_ctl(EPOLL_CTL_ADD 监听fd)
   → epoll_wait() → accept() [三次握手已完成，从全连接队列取出连接]
   → recv()/readv() [从内核接收缓冲区读数据] → 解析 HTTP → writev()/sendfile() [写内核发送缓冲区]
   → close() [四次挥手，TIME_WAIT]
```

本目录在原始源码基础上**逐行添加中文注释**（每一行代码都有自己的注释，不是逐段注释），
注释内容将 Linux 操作系统理论与该行代码一一对应。

## 二、涉及的核心操作系统理论

### 1. 用户态/内核态与系统调用
- CPU 分为用户态（Ring 3）与内核态（Ring 0）。nginx 调用 `socket()/recv()/epoll_wait()` 等
  都会触发 `int 0x80`/`sysenter` 陷入内核态，由内核代为操作网卡、协议栈，完成后返回用户态。
- 每次系统调用都有上下文切换开销，这是 nginx 用 epoll 把"多次系统调用合并为一次等待"的根本动机。

### 2. TCP/IP 协议栈与三次握手（对应 `ngx_event_accept.c`）
- Linux 内核网络分层：应用层(socket 层) → TCP 层(tcp_*) → IP 层(ip_*) → 网卡驱动。
- 服务端 `listen()` 后，内核为该监听 socket 维护**两个队列**：
  - **半连接队列（SYN 队列）**：收到客户端 SYN、回复 SYN+ACK 后，连接处于 `SYN_RCVD`，
    长度受 `net.ipv4.tcp_max_syn_backlog` 限制；
  - **全连接队列（accept 队列）**：收到客户端最后一个 ACK、连接进入 `ESTABLISHED` 后放入此队列，
    长度 = min(listen 的 backlog 参数, `net.core.somaxconn`)。
- **`accept()` 做的事情只是从全连接队列头部取出一个已经 ESTABLISHED 的连接**，
  并为新连接分配一个新的 fd（五元组：源IP、源端口、目的IP、目的端口、协议）。
  三次握手本身由内核协议栈自动完成，不需要应用参与。
- `close()` 触发四次挥手；主动关闭方最后进入 `TIME_WAIT`，停留 2*MSL（约 60 秒）。

### 3. 非阻塞 I/O 与错误码（对应 `ngx_recv.c`/`ngx_send.c`）
- 阻塞 I/O：缓冲区无数据时进程睡眠（内核把进程挂到等待队列）；非阻塞 I/O：立即返回 -1，errno=EAGAIN/EWOULDBLOCK。
- nginx 全部使用非阻塞 socket（`ioctl(FIONBIO)` 或 `fcntl(O_NONBLOCK)`），配合事件机制实现单进程处理海量连接。
- `EINTR`：系统调用被信号打断，需重试；`EPIPE`：对端已关闭连接仍写（触发 SIGPIPE）。

### 4. I/O 多路复用：select 与 epoll（对应 `modules/` 目录）
- **select**：每次调用把整个 fd_set（默认 1024 个 fd 上限）从用户态拷入内核并线性扫描，O(n)；
- **epoll**：
  - `epoll_create`：内核建立**红黑树**（管理所有被监听 fd）与**就绪链表**（存放有事件的 fd）；
  - `epoll_ctl(ADD/MOD/DEL)`：向红黑树增删改节点，并在 socket 等待队列上注册回调 `ep_poll_callback`；
  - 数据到达 → 网卡中断 → 协议栈接收 → 回调把该 fd 加入就绪链表 → `epoll_wait` 直接返回就绪链表，O(1)；
  - **LT 水平触发**：只要接收缓冲区仍有数据就一直通知（nginx 默认 LT）；**ET 边缘触发**：仅状态变化时通知一次。
- 这就是 nginx 单机数万并发连接的核心（C10K 问题的解法）。

### 5. 惊群（Thundering Herd）与 accept_mutex（对应 `ngx_event.c`/`ngx_event_accept.c`）
- 多个 worker 进程都阻塞等待同一个监听 fd 时，一个连接到达会唤醒所有进程，但只有一个 accept 成功，
  其余白白唤醒（上下文切换浪费），称为"惊群"。nginx 用 accept 互斥锁（`ngx_accept_mutex`）保证同一时刻
  只有一个 worker 监听端口。0.1.0 版本对应代码在 `ngx_event.c` 的进程初始化与事件循环中。

### 6. socket 选项与 TCP 特性（对应 `ngx_socket.c`）
- `SO_REUSEADDR`：允许绑定处于 TIME_WAIT 的地址，服务器重启无需等待 2*MSL。
- `TCP_NODELAY`：禁用 Nagle 算法（Nagle 会攒小包合并发送，降低实时性）；HTTP 应答要求低延迟，故禁用。
- `TCP_CORK`（Linux）/`TCP_NOPUSH`（FreeBSD）：与 Nagle 相反，强制"塞住"小包直到解除，
  配合 `writev()`+`sendfile()` 让响应头和文件一次高效发出，解除时一次性冲刷（`ngx_tcp_push`）。

### 7. 零拷贝 sendfile（对应 `ngx_linux_sendfile_chain.c`）
- 传统读文件再发网络要 4 次拷贝 + 4 次用户/内核态切换；
- `sendfile()` 全程在内核态完成：磁盘 → 页缓存 →（网卡聚合散布 DMA）→ 网卡，用户态零拷贝。

### 8. 其他
- **网络字节序**：网络协议统一大端序，`htons/ntohs/htonl/ntohl` 在主机序与网络序间转换（`ngx_inet.c`）。
- **readv/writev 分散读/集中写**：一次系统调用读写多个不连续缓冲区（`ngx_readv_chain.c`/`ngx_writev_chain.c`），
  减少系统调用次数，是"系统调用开销"理论的应用。
- **信号机制**：worker 收到 SIGTERM/SIGQUIT 优雅退出；`EINTR` 即信号中断系统调用的体现。
- **共享内存 + 原子操作**：多 worker 间的锁（`ngx_spinlock.c`/`ngx_shared.c`）依赖 CPU 原子指令。

## 四、注释约定

1. **逐行注释**：每一行有效代码（含声明、赋值、if/for、return、宏、`}`、`#endif` 等）都拥有属于自己的
   一条中文注释，行短时放行尾 `/* ... */`，行长时放上一行；**绝无一条注释覆盖多行代码的逐段注释**。
2. 原始代码一个字符都没有改动（可用 `git diff` 验证：删掉注释行后与官方 0.1.0 原版完全一致）。
3. 原有的英文版权与说明注释原样保留。
4. 注释不止翻译"这行在干什么"，还结合上述理论说明"内核/协议栈层面发生了什么"。
